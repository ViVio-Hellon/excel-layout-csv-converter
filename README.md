# エクセル → CSV 変換器

過去の日報ブック(xlsx)を、**日報管理ツールとまったく同じCSV**に変えます。

使い方は3つ。どれも**同じ変換**を通ります。

| | |
|---|---|
| **デスクトップ版** | `ExcelCsvConverter.exe` ── 窓で動きます。**ポートを使いません**([docs/デスクトップ版.md](docs/デスクトップ版.md)) |
| 画面から(ブラウザ版) | `Start.vbs` を実行 ── ドラッグで放り込み、進捗を見ながら変換 |
| コマンドから | `python convert.py <ファイル or フォルダ> ... --out <出力先>` |

デスクトップ版とブラウザ版は**同時に動きません**。後から開いたほうが
自分で止まります(先に動いているほうには手を出しません)。

## 画面から使う

`Start.vbs` を実行すると待機画面が出て、準備ができ次第アプリ画面へ
切り替わります。**利用者が実行するファイルは1つだけ**です。

```
Start.vbs   通常の起動(コンソールを出しません)
start.bat   起動しないときの診断用(黒い画面に理由が出ます)
stop.bat    バックエンドの停止
```

画面は**タブで4つ**に分かれています。

| タブ | 受けるもの | 出すもの |
|---|---|---|
| **変換** | .xlsx / .xlsm | 1日・1ラインごとに4本組CSV(日報管理ツールと同じ) |
| **機側データ集計** | .xlsx / .xlsm / **.csv** | VBAと同じ転記を**1本のCSV**([docs/機側データ集計.md](docs/機側データ集計.md)) |
| **板集計** | 日報管理ツールが書いた日ごとのCSV | 期間ぶんを**1本**にまとめ、**グラフ**にして CSV / Excel へ([docs/板集計.md](docs/板集計.md)) |
| **設定** | ― | どこを読んで、どこへ出すか + **配布設定**([docs/配布設定.md](docs/配布設定.md)) |

- **設定タブ**で、入力元・出力先・ライン・参照用マスタ・停止内訳CSV・
  板データ参照パスをパスで指定します(保存するとこの端末に残ります)。
  1台で決めた設定は**配布設定**で配れます
- **ドラッグで放り込め**ます。フォルダごとでも構いません
- **一度に100本まで**。進捗バーに何本目か・あとどれくらいかが出ます
- **ダウンロードはしません。** 出力先フォルダへ、この端末のPythonが直接書きます

### 画面は1枚しか開けません

2枚開けると、2つの画面が同じ作業状態を奪い合います ── 片方で「変換開始」、
もう片方で「中止」。片方で保存した設定を、もう片方は古いまま表示。どちらが
本当か見分けがつきません。**混乱のもとなので、開くこと自体をお断りします。**

| | |
|---|---|
| 2枚目のタブ・別のブラウザ・直接URL | 開いた側が「この画面は開けません」で止まります |
| `Start.vbs` をもう一度実行 | 「すでに起動しています」。2つ目のバックエンドは起動しません |
| **再読込** | 断りません(同じタブは持ち主のまま) |
| 閉じて開き直す | 開けます(10秒ほどで空きます) |

止め方は3段です。プロセス(`launch_guard.py`)、サーバ(`converter/screen_lock.py`)、
ブラウザ(`app/static/js/screen.js`)。**どれか1つでは足りません** ── 複製した
タブはブラウザ側でしか見分けられず、別のブラウザはサーバ側でしか止められない
からです。

くわしくは [docs/運用.md](docs/運用.md)。

## コマンドから使う

```bash
# フォルダごと
python convert.py 2026.08 --out C:\出力

# ファイルを名指し、入れる先のラインを指定
python convert.py a.xlsx b.xlsx --out out --line LS

# 書かずに、読めるか・数が合うかだけ見る
python convert.py 2026.08 --check

# 機側データ集計(VBAと同じ転記)も1本のCSVに出す
python convert.py 2026.08 --out out --tally

# 停止の「内訳」名を出す(参照用マスタの置き場所)
python convert.py 2026.08 --out out --ref \\サーバ\共有\参照用マスタ

# 停止の「内訳」名をCSVで持つ(メモ帳で直せる。マスタより先に読みます)
python convert.py 2026.08 --out out --stop-csv \\サーバ\共有\停止内訳.csv

# 機側データ集計で読める相手かどうかを先に見る(停止3枠なのに読めないものを探す)
python scripts/ブックを点検.py 2026.08

# 変換は1日・1ラインごとに5本出します(4本は日報管理ツールと同じ、
#   5本目 機側データ集計_<ライン>_<日付>.csv は集計の材料)
#   → あとで日付フォルダを集計に入れても、ブックから集計したのと同じ結果

# 機側以外のシート(ほかのライン)も集計に入れる ── **VBAは機側だけ見ます**
python convert.py 2026.08 --out out --tally --any-sheet
#   → 機側データ集計_LS_2026.08.23-2026.08.27.csv / 機側データ集計_HVC_….csv
#     (ラインごとに1本。機側には板に無い欄があるので分けます)
```

| 返り値 | 意味 |
|---|---|
| 0 | 全部読めて、数も合った |
| 1 | 読めなかったファイルがある |
| 2 | 読めたが、**数がシートと合わない**(書いてはある) |

## 何が出るか

1日・1ラインごとに4本 + 列の説明:

```
<出力先>/<ライン>/集計/<年.月>/<日>/
    集計_2026-08-23_LS.csv       直ごとの合計(枚数・重量・稼働率・生産性 …)
    集計明細_2026-08-23_LS.csv   打った行そのもの
    停止内訳_2026-08-23_LS.csv   停止の分類ごと・項目ごと
    計算内容_2026-08-23_LS.csv   数字の出しかた(途中式)
    CSVの読み方.txt              列の説明
```

BOM付き UTF-8 なので、Windows の Excel でそのまま開けます。

> **4本は写し(`vendor/`)の版 v3.96.0 の決まりで作ります。** 日報管理ツールは
> v4.44.14 から、分類1・内訳番号99 を管理ロスから外して「その他停止」に数え、
> `集計_` に「その他(分)」の欄を足しました。この変換器の `集計_` には
> その欄が無く、99 は**管理ロス設備停止(分)に入ります**(停止合計・稼働率は
> 同じ)。そろえるには写しの採り直しが要ります(VENDOR.md)。
> 停止内訳CSVの `1,99,,`(名前の空の 99)は日報管理ツールの決まりどおり
> 正しい行として扱い、直せとは言いません(1.11.1)。

## なぜ「まったく同じ」と言えるのか

集計CSVの出どころは**集計テーブル**で、流れはこうなっています:

```
xlsx → 日報の明細 → 保存 → 集計を作り直す → CSV
```

ここを自前で書き直すと、**同じ数を2通りの道で出す**ことになってずれる
余地ができます。ずれても数は出てしまうので、気づけません。

だから**日報管理ツールと同じ関数をそのまま通します**。使い捨ての SQLite
を1つ作って通し、終わったらDBごと捨てる ── 残るのはCSVだけです
(`converter/run.py`、写しは `vendor/`。[VENDOR.md](VENDOR.md))。

一致は作り込んだものではなく、**同じコードを通した結果**です。

## 座標が合っているかを、毎回確かめます

古いブックはテンプレートが年によって違うことがあり、**列が1つずれていても
数は出てしまいます**。出たことと、合っていることは別です。

さいわいシートは自分で合計を持っているので(`AA55`/`AB55` …、`T4`/`V4`/`X4`)、
読んだ明細を足した数と突き合わせます:

```
  [   2/13] 2026.08.23.機側.xlsx  ○ 2026年8月23日 機側→LS 5ページ 40行  9項目すべて一致
  [   7/13] 2026.08.27.HVC.xlsx   ! 2026年8月27日 HVC→HVC 3ページ 18行  1/9項目がちがいます ── 2直 重量: 読んだ数 7002 / シート 7010 (差 -8) ×
```

合わなかったものは最後にもう一度名指しし、返り値 2 で終わります ──
**黙って通しません。**

### シートが持っていない合計は、比べません

実物には**合計欄が空のまま**のブックがあります(式の結果が保存されて
いない、など)。空欄を0として比べると
`停止 合計(分): 読んだ数 870 / シート 0 ×` と出ます ── **読めているのに
ずれていると言う**ことになるので、持っていないものは比べず、こう並べます:

```
  ○ 2025年7月15日 機側→LS 4ページ 27行  8項目すべて一致。シートが持っていないので比べていない項目: 停止 合計(分)
```

直合計が入っているのに日計だけ古いブック(合計式が計算し直されていない)も
ありました。そのときは**直合計の足し算と比べ**、
`シートの日計 枚数(28)が直合計の足し算(62)と食い違っています` と出します ──
ずれているのはシートの側です。

### 読むときに手を入れたことは、必ず出します

作業日の書き方が年によって違います(`2025/7/15` `2025-07-15` `2025.7.15`
`20250715`、Excelの日付の数)。同じ日付なので読める形に直しますが、
**黙って直しません**:

```
     ※ 作業日を 2025/7/15 → 2025年7月15日 として読みました(作業日(E1))
```

## 確かめたこと

実機のブック13本(機側=コイル 7本 / HVC=板 6本)で:

| | |
|---|---|
| 読めた | 12/13 本(残る1本は別レイアウト。下記) |
| シート自身の合計との突き合わせ | **12本すべて 9項目一致**(直ごとの枚数・重量、日計、停止) |
| 日報管理ツール本体の出力との比較 | **48本すべてバイト一致** |

本体側は実際のHTTPの取り込み口(`/api/settings/import/upload`)を通した
ものと比べています ── 現場で押されるのと同じ道です。

## コイルと板

**座標は同じです。** 変わるのは「どの欄を使うか」だけでした:

| 欄 | 列 | コイル | 板 |
|---|---|---|---|
| コイル縦割 / コイル横縦割 | AQ / AR | ○ | － |
| 係数処理ﾛｯﾄ数 | B | ○ | － |
| 合紙 | O | － | ○ |
| ＶＣ種別 | R | － | ○ |

どちらも同じ読み手で通り、合計も完全に一致しました。

## 読める形・読めない形

読めるのは**日付シート**です ── 1ファイル = 1日ぶん・3直ぜんぶの24時間割で、
シート名が `2026年8月23日_機側` の形をしているもの。座標は
[docs/座標表.md](docs/座標表.md)(コードから起こしています)。

**読めないもの**: 1直ぶんの入力/印刷シート(シート名が
`2026年8月31日3直_HVC` の形で、作業日が `B1`、ラインが `B2`)。これは
別レイアウトで、いまは対象外です。必要なら足せます。

## ラインの決め方

シートには `機側` `HVC` のような現場の呼び名が入っています。ツールの
ライン名とは違うので当たりを付けますが(`機側` → `LS`)、**外れることが
あるので `--line` で上書きできます**。当たらなければ、黙って入れずに
断ります。

## 要るもの

**Python 3.11 以上だけ。追加ライブラリはありません** ── 画面のほうも同じです
(`http.server` / `zipfile` / `xml.etree` / `csv` / `sqlite3`)。現場のPCへ
配るものなので、入れるものが増えるほど「動かない」理由が増えます。

## テスト

```bash
python -m unittest discover -s tests -t . -q
```

画面と起動基盤のぶんも同じところで走ります ── 2枚目を断ること、
再読込は断らないこと、100本の上限、進捗、中止、多重起動の判定、
起動ファイルの文字コードまで(`tests/` の一覧は [docs/設計.md](docs/設計.md) §8)。

**実物のブックは置いていません** ── 作業者名も納入先も実名なので
(`.gitignore`)。テストは同じ座標へ同じ形の値を置いたブックを自分で
組み立てます(`tests/_fixture.py`)。

## 中身

起動の仕組みと業務機能を分けています(社内「汎用Webアプリ作成 基盤仕様書」
2.5)。構成は同じ作りの `python-web-tools`(梱包資材総合ツール)にそろえて
あります ── 起動・停止・監視の作法を覚え直さずに済むようにするためです。

```
Start.vbs / start.bat / stop.bat   利用者の入口(通常 / 診断 / 停止)
start_app.py            起動の開始点。環境を整え、起動してよいかを決める
launch_guard.py         多重起動の判定(応答で確かめる)
boot_server.py          まず待機画面を出し、本体へ引き継ぐ
server.py               待ち受けと、受け渡しの形(Request / Response)
process_manager.py      対象のアプリだけを安全に止める
convert.py              コマンド版の入口
requirements.txt        **何も要りません**(そう書き残してあります)

app/                    画面層だけ
  __init__.py           組み立てと守り(Host・オリジン・合言葉・画面の占有)
  shell.py              外枠(base.html)に渡す値
  routes/               health / screen / settings / input / job
  templates/            base.html + index.html
  static/css/           tokens / base / layout / components
  static/js/            api / screen / health / toast / busy / progress / views

converter/              業務と基盤
  app_config.py         アプリ固有値(ID・ポート・上限・ローカル領域)
  user_settings.py      設定部(入力元・出力先・ライン・参照用マスタ・停止内訳CSV)
  stop_reasons.py       停止内訳(記号→内訳名)。**出どころ2つのどちらを読んだか言う**
  cells.py              xlsx のセル(**ふりがなを値に混ぜない**)
  books.py              ブックの全シート(集計が使う)
  screen_lock.py        **画面を1枚に絞る**
  jobs.py               変換の実行・進捗・中止
  intake.py             ドラッグで受け取ったブックの置き場所
  idle_exit.py          画面が居なくなったら終わる
  boot_screen.py        起動待機画面の骨格
  logging_utils.py      ログ(launcher.log / app.log)
  run.py                xlsx → CSV の道すじ
  check.py              シート自身の合計との突き合わせ(純粋)
  totals.py             シートの合計欄(**空欄と0を区別して**拾う)
  workday.py            作業日の書き方をそろえる(直したことは出す)

vendor/                 日報管理ツールの写し。**ここは直しません**
config/app.json         アプリごとに決める値(ここだけ直せば配れます)
docs/設計.md            作りの説明
docs/はじめに読む_起動と使い方.md   現場向けの手順
docs/変更履歴.md        版ごとに何が変わったか
docs/座標表.md          どのセルがどの欄か(コードから起こす)
scripts/座標表を出す.py  ↑ を書き直す
tests/
```

書くもの(ログ・キャッシュ・設定・受け取ったブック)は**すべて
`%LOCALAPPDATA%\ExcelCsvConverter`** へ行きます。アプリ本体は共有フォルダに
置かれることがあるので、そちらへ書くと利用者どうしでぶつかります
(基盤仕様書 2.7)。
