# 機側データ集計 ── VBAと同じ転記を1本のCSVに

Excel VBA の「機側データ集計」(UserForm の実行ボタン → `機側データ集計`)が
やっていた**読み取りと転記**を、そのままCSVへ出す機能です。

    ブック何冊 → 対象シートを選ぶ → 8行目から拾う → 1枚の表へ積む
               → 空欄を2通りのやり方で埋める → CSV 1本

中身は `converter/tally.py`。既存の変換(1日・1ラインごとの4本組CSV)とは
**別の出口**で、あちらには手を入れていません ── 日報管理ツールと1バイトも
違わないことを確かめてあるので、混ぜると確かめ直しが要ります。

## 使いかた

**画面から** ── 上の<b>「機側データ集計」タブ</b>へ切り替え、ブックかCSVを
放り込んで「集計する」。出力先フォルダへ
`機側データ集計_LS_2026.08.23-2026.08.27.csv` の形で、**ラインごとに1本**
書きます(ラインと日付の幅が名前に入ります)。

**このタブでは変換(4本組のCSV)はしません。** 4本組が要るときは「変換」タブで
別に実行してください。受け取り置き場は**タブごとに分かれている**ので、
片方を片づけても、もう片方は残ります。

**コマンドから**

```bash
python convert.py 2026.08 --out C:\出力 --tally
```

`--check` と一緒に使うと、**書かずに行数だけ**数えます。

## 受けるもの

| 渡すもの | どう読むか |
|---|---|
| ブック(.xlsx / .xlsm) | 下の「何を拾うか」のとおり |
| **変換が出した集計明細CSV** | 1行=1行で読みます。日付は**行ごと**(1本に何日ぶんも入り得ます) |
| **変換が出した停止内訳CSV** | 行の材料にはせず、**停止の記号→内訳名**に使います |
| **前に出した集計CSV**(1行目がこの見出し) | そのまま**積み増し**ます(VBAが集計シートへ追記していたのと同じ) |
| **シートをCSVで保存したもの**(A1が「集計」) | ブックと同じに読みます。日付は**作業日の欄(E1)**から採ります |
| 変換が出した集計CSV・計算内容CSV | **材料になりません**。理由を言って飛ばします |
| それ以外のCSV | **断ります**。何が入れられるかを画面に出します |

CSVの文字コードは `utf-8-sig` → `cp932` → `utf-8` の順に試します
(Excelの「CSV(コンマ区切り)」は日本語Windowsでは CP932 です)。

積み増したときも、**空欄の埋め方は全体へもう一度かかります** ── VBAが追記の
あとに後処理を回していたのと同じです。

### 日付フォルダをそのまま放り込めます

変換すると、1日・1ラインにつき5本出ます:

```
C:\出力\LS\集計\2025.07\15\集計_2025-07-15_LS.csv
                              集計明細_2025-07-15_LS.csv
                              停止内訳_2025-07-15_LS.csv
                              計算内容_2025-07-15_LS.csv
                              機側データ集計_LS_2025.07.15.csv   ← **集計の材料**
```

5本目が**機側データ集計の材料**です。変換のときに、4本組とは別に
**シートから直に拾って**残しています。このフォルダを集計タブへドラッグ
すれば、**ブックから集計したのと1行1列まで同じ**結果になります。

**なぜ5本目が要るのか。** 4本組は日報管理ツールが持っている欄だけで、停止は
**記号**(AJ〜AO)しか入っていません。VBAの機側データ集計が読むのは
**内訳**(S〜X)のほうなので、4本組だけを材料にすると

    シートから集計  … 内訳側(「材料待ち」など)
    CSVから集計     … 記号側(「ヲ」など)

と**同じシートなのに答えが変わります**。5本目はシートから拾ったものなので、
そこが揃います。

**同じ日を2回積みません。** 日付フォルダには材料と集計明細の両方が入って
いるので、両方積むとその日が二重に数えられます。**元に近いほう**だけ使い、
飛ばしたほうは理由を出します:

    ブック > 変換が残した材料・前に出した集計 > 集計明細

集計と計算内容は、受け取る前に外します(一度に100本までなので、材料に
ならないものに枠を使わせません)。

### フォルダの階層は問いません

**どう分けてあっても、どの深さでも同じ結果です。** 画面はフォルダを
いちばん下までたどり、**ファイル名の順**に積みます(受け取り置き場へ写す
ときに名前の最後の1つだけを採るので、階層は消えます)。

| | |
|---|---|
| 日付フォルダのまま | `LS\集計\2026.08\23\…` をそのまま落とす |
| 全部ひとまとめ | 1つのフォルダに集めて落とす |
| 深さがばらばら | 途中のフォルダが何段あっても同じ |
| 停止内訳CSVが別の場所 | **引けます。** VBAは同じフォルダの中だけを見ます |

実物の7冊＋CSV21本で、この3通り(日付フォルダのまま / 全部平ら /
でたらめな深さ＋同じ日を2か所)を通して**出てきたCSVがバイトまで同じ**で
あることを確かめました(どれも263行)。

**気をつけるのは名前です**(階層ではありません):

- **積む順はファイル名の順**です。日報管理ツールのCSVは名前に日付が入って
  いるので時系列どおりになります ── 名前を日付と違う順になるよう付け替え
  ると、上詰めで埋まる**その塊の1行目だけ**値が変わります
  (実測で143行中1行)
- 同じ名前が2本来たら `(1)` を付けて両方受け取り、**同じ日・同じラインなら
  強いほうだけ**使って、飛ばした理由を出します
- 前に出した集計(`機側データ集計_…csv`)は**名前からラインを読みます**
- 一度に受けられるのは **100本**(`config/app.json` の `max_files`)。
  日ごとに4本のうち `集計_` と `計算内容_` は受け取る前に外すので1日3本 ──
  **1回で1か月ぶんくらい**です。年ごと落とすなら月で分けてください

コマンド版(`python convert.py <フォルダ> --tally`)もフォルダを下まで
たどります(こちらは**パスの順**で、拾うのは `.xlsx` / `.xlsm` だけです)。

### 停止は「振り分け後」を使います

シートは停止を2か所に持っています。

```
S〜X      作業停止内訳-1/2/3   停止名 + 時間      ← **振り分け後。こちらが中身**
AJ〜AO    作業停止①②③        記号 + 時間        ← 振り分け前(AJ4 に帯があります)
```

現場は**振り分け前に記号のまま先に書き込み**、それを左の欄へ停止名として
振り分けます。だから数えるのは**振り分け後**です ── VBAの機側データ集計も、
シート自身の合計(T4/V4/X4)も、このツールの検算もこちら側です。
振り分け前は作業用の欄なので、書き損じが入っていても数えません。

日報管理ツールが持っているのは**振り分け前(記号)**のほうなので、
集計明細CSVから読むときだけ記号になります(材料CSVがあればそちらが優先)。

### 集計明細CSVからは、同じ振り分けをやり直します

集計明細CSVには**振り分け前(記号)しか入っていません**。そこで、現場の
シートがやっているのと同じ振り分けを、こちらでやり直します ──
**記号の文字種**で決めます:

| 記号 | 入る枠 |
|---|---|
| 数字(`0` `1` …) | 作業停止内訳-**1**(管理ロス) |
| 片仮名(`ヲ` `タ` `ﾍ` …) | 作業停止内訳-**2**(段取り・突発) |
| 英字(`E` `B` …) | 作業停止内訳-**3**(ハンドリング) |

**位置(①②③)ではありません。** 作業停止①に片仮名が入っていれば、それは
内訳-2です。位置のまま入れると、日報管理ツールが出す `集計_…csv` の
停止3分類ともシート自身の合計(T4/V4/X4)ともずれます。

判定は日報管理ツール側の `classify_stop_code`(VBA の `CheckCharType` の
移植)をそのまま呼びます ── 書き写すと、片方だけ直したときにずれます。

| | |
|---|---|
| 見る枠 | **①〜⑤**。いまのCSVには①②③の列しかありませんが、増えても拾えます |
| 同じ枠に2つ以上 | **行を増やします**(2行目以降は停止だけ ── 作業時間を写すと二重に数えます)。現場のシートも、振り分け後を次の行へ書き下げています |
| 分けられない記号 | 全角の `Ｂ`、ローマ数字の `Ⅾ` など。**集計に入れず、そう言います**(シート自身の振り分けも同じで、入っていませんでした) |
| 作業時間が空 | 終了時刻があるなら **0分**(CSVは0を空欄で出します) |
| 同じ行が2回 | 同じ 日付・直・ページ・行 は**1回だけ**(VBAと同じ) |

### 停止の「内訳名」はどこから来るか

5本目の材料CSVには、シートの**内訳名がそのまま**入っています(VBAと同じ)。
以下は、**材料CSVが無く、集計明細CSVから読むとき**の話です。

集計明細CSVに入っているのは**記号**(`タ` `E` `0`)だけです。シートから
直接読むときは内訳名(S・U・W列の「材料待ち」など)がそのまま入りますが、
CSVから読むときは名前を引いてきます。**先に見るほうから順に**:

1. 一緒に入れた**停止内訳CSV**の「内訳」列(その日に使われていた名前)
2. 設定部の**停止内訳CSVの置き場所**(無ければ**参照用マスタ**の表)
3. どちらでも引けなければ、**記号のまま入れて、そう言います**

3になった記号は結果の一覧に並びます ── 黙って空にはしません。

**分類1・内訳番号99 だけは、名前が空でよい記号です**(日報管理ツール
v4.44.13 からの決まり。`converter/stop_reasons.py` の `BLANK_NAME_CODES`)。
名前の欄を**空のまま**作業停止内訳-1 に入れ、時間は数えます(隠しません)。
その日の停止内訳CSVで空だった 99 には、設定部のマスタの名前も入れません。
知らせは「記号のまま入れました」ではなく、`内訳番号99(名前なし) ○件・○分`
の1行です ── 機側週計(VBA_CSV_Coil)の「集計_確認」と同じ出し方です。

### 集計明細CSVから読むと、ブックと違うことがあります

**5本目の材料CSVがあれば起きません**(そちらが優先されます)。材料CSVを
消してしまった・古い版で変換した、などで集計明細から読むときの話です。

実物の2025年7月15日では、**ブックから32行・集計明細CSVから33行**でした。
**停止の分は 内訳-1 80分 / 内訳-2 640分 / 内訳-3 110分 で、両方とも同じ**
です(2026.08.23〜27 の5日ぶんも、6日すべて一致しました)。

**1行だけ違うのは、現場が振り分け後を「次の行」へ書き下げるから**です。
記号は1行にまとまっているので、こちらは溢れ行を作って同じ形にします ──
書き下げ先の行に**その行自身の終了時刻**も入っているとき、1行多く出ます
(例: 2026年8月27日の86〜87行)。停止の分は変わりません。

停止の**内訳(S・U・W列)だけが書かれていて記号(AJ・AL・AN列)が空**の行も
あります。日報管理ツールは記号+時間を読むので、その行は集計明細CSVに出て
きません(VBAの機側データ集計は内訳+時間を読むので、こちらには出ます)。
**停止2枠のブックが混じっているからではありません** ── このブックは3枠です。
**ブックが手元にあるならブックを入れたほうが、VBAと同じ行数になります。**

## 何を拾うか

| | |
|---|---|
| 対象シート | `A1` が「集計」**かつ**シート名に `_機側` を含むもの(1冊に複数枚あれば全部) |
| ほかのライン | **既定では読みません。** 「機側以外のシートも読む」で、シート名の縛りだけ外せます(下記) |
| ふりがな | `A1` の値に**ふりがなは混ぜません**。実物の2025年のブックは `集計` にふりがな(`シュウケイ`)が付いていて、混ぜると1枚も拾えませんでした(`converter/cells.py`) |
| 日付 | **シート名の `_` より前**(`2026年8月23日_機側` → `2026年8月23日`) |
| 拾う範囲 | 8行目から、**L列(終了時刻の「時」)に何か入っている一番下の行**まで |
| 拾う行 | L列が空でない **または** S・T / U・V / W・X のどれかの対が両方入っている行 |

**停止だけが書かれた行も拾います。** 「内径カット 30分」のように作業時間の欄が
空で停止だけ書かれる行が実物にあり、VBAも後からこの条件に直されています。

**L列が1つも無いシートからは1行も拾いません。** VBAは最終行をL列で決めるので
`8 To 1` の繰り返しになり、停止だけの行があっても回りません。同じにしてあります。

## 列の対応(停止3枠のみ)

**20列目まではどのラインでも同じで、後ろだけ入れ替わります。**

| CSV | 見出し | シートの列 |
|---|---|---|
| 1 | 日付 | シート名 |
| 2 | ロット№ | D |
| 3 | 材・調質 | E |
| 4 | サイズ | F |
| 5 | 検入 | I |
| 6 | 用途コード | AE |
| 7 | 用途名 | AF |
| 8 | 納入先 | AG |
| 9 | 梱包数 | P |
| 10 | 包数 | Q |
| 11 | 作業時間（分） | AC |
| 12 | 作業停止内訳-1 | S |
| 13 | 時間（分） | T |
| 14 | 作業停止内訳-2 | U |
| 15 | 時間（分） | V |
| 16 | 作業停止内訳-3 | W |
| 17 | 時間（分） | X |
| 18 | etc | AI |
| 19 | 包装仕様NO | AH |
| 20 | 作業人数 | N |

ここから先はラインで変わります:

| | 21 | 22 | 23 |
|---|---|---|---|
| **コイル**(機側 / `LS`) | 縦割 `AQ` | 横割 `AR` | 係数処理ﾛｯﾄ数 `B` |
| **板**(そのほかのライン) | 合紙 `O` | ＶＣ種別 `R` | ― |

コイルの3列が**VBAの転記列そのまま**です。板の2列はVBAに入っていません ──
機側では使わない欄なので、機側ライン用のマクロには要らなかったものです。
**板の集計には要る**ので足しました(利用者の言葉で「板、コイルで集計が違う」)。

どのラインをコイルとみなすかは `config/app.json` の `lines.coil`(既定
`["LS"]`)です。**ここに無いラインは板あつかい**になります ── コイルの
ラインが増えたら、ここに足してください。

**「時間（分）」が3回出ます。** VBAの見出しをそのまま使っているためで、
変えると「VBAの集計シートと同じもの」ではなくなります。

**停止2枠のブックは読みません。** AA以降が2列ぶん手前にある別テンプレートで、
黙って読むと別の欄の値が入ります。7行目の見出しを確かめて、違えば理由を出して
そのシートを飛ばします。

## 空欄の埋め方 ── **順番で結果が変わります**

| 順 | 対象 | やり方 |
|---|---|---|
| ① | ロット№・材・調質・サイズ・検入・用途コード・用途名 | **上の行**の値で埋める |
| ② | 納入先 | **同じロットで最初に現れた値**で埋める |
| ③ | 作業人数 | **上の行**の値で埋める |
| ④ | etc・包装仕様NO・縦割・横割・係数処理ﾛｯﾄ数 | **同じロットで最初に現れた値**で埋める |

①でロット№を埋めてから、②と④がそのロットを鍵にします。**並べ替えないでください。**

2つの癖もVBAのままにしてあります。

- **先頭が空の列は、最初に見つかった値で埋まります**(上詰めの初期化)。
  作業人数が1行目だけ空のとき、下の値が入ります
- **ブックをまたいでも上詰めは続きます**。VBAは1枚の集計シートへ積むので、
  前の日の最後の値が次の日の先頭の空欄に入ります

**書いていない数は作りません。** 梱包数・包数・作業時間・停止の時間は埋めません
(VBAも埋めていません)。

## なぜ機側のシートだけなのか

VBA がそう書かれているからです ── 件数を数えるところと、転記するところの
**2か所とも**同じ条件です:

```vb
If ws.Range("A1").Value = "集計" And InStr(ws.Name, "_機側") > 0 Then
```

マクロが**機側ライン用に作られた**ためで、紙の様式(座標)はほかのラインでも
同じです(`docs/座標表.md` ── コイルと板で使う欄が違うだけ)。

### どのラインでも、拾い方は同じ

紙の様式(座標)はラインが変わっても同じです。**使う欄が違うだけ**で:

| | 機側(コイル) | HVCなど(板) |
|---|---|---|
| 縦割・横割(AQ・AR) | 使う | 空 |
| 係数処理ﾛｯﾄ数(B) | 使う | 空 |
| 合紙(O)・ＶＣ種別(R) | 空 | 使う |

**だからラインごとに、分けて・違う並びで出します。**

```
コイル  日付 … 作業人数, 縦割, 横割, 係数処理ﾛｯﾄ数   (23列。VBAのまま)
板      日付 … 作業人数, 合紙, ＶＣ種別              (22列)
```

先頭20列(日付＋共通19項目)は**同じ位置**です ── 並べて見てもずれません。

### 機側以外のシートも読ませたいとき

画面なら集計タブの**「機側以外のシートも読む」**、コマンドなら
`--any-sheet`、点検なら `--any-sheet`。外れるのは**シート名の縛りだけ**で、
`A1`が「集計」であることと**停止3枠の見出し**は変わらず見ます ── 別の様式を
黙って読まないためです。

出すCSVは**ラインごとに1本**で、並びもラインのものになります:

```
機側データ集計_LS_2026.08.23-2026.08.27.csv     機側(コイル)  23列
機側データ集計_HVC_2026.08.26.csv               板            22列
```

ラインは**シート名の「_」より後**から採り、日報管理ツールの呼び名に
直します(`機側` → `LS`)── 同じラインの行が、ブックからは「機側」、
変換したCSVからは「LS」として別々に分かれないようにするためです。

**空欄の埋め方もラインごとです。** 上詰めは「上の行」を見るので、混ぜたまま
埋めると板の行に機側のロット№や用途名が入ります ── 分ける一番の理由がこれです。

**入れた時点でVBAと同じ結果ではなくなります**(VBAなら0行になるシートを
読むので)。そのため結果の言葉に

```
機側以外のシートも読みました(VBAは名前に「_機側」を含むシートだけ見ます)
```

と出ます。機側以外のシートばかりで0行になったときは、逆に

```
機側以外のシートばかりでした ──「機側以外のシートも読む」を入れると、同じ様式なら読めます
```

と出ます。

## 読める相手かどうかを、先に確かめる

**探すのは「停止3枠なのに読めないブック」です。** 2枠のブックは読みません
(列が2つずれていて、黙って読むと別の値が入ります)。

画面なら、集計タブの**「確かめるだけ(CSVを書きません)」**で実行します。
1枚につき1行、拾える行数か、**拾わない理由**が出ます。

まとめて見るなら:

```bash
python scripts/ブックを点検.py \\サーバ\共有\日報\2026
```

```
読める 枠    行数  ファイル / シート
○     3枠       48  2026.08.24.xlsx / 2026年8月24日_機側
×     2枠        0  2024.05.11.xlsx / 2024年5月11日_機側
                 └ 停止2枠のブックです(作業時間が AA 列 ── 3枠より2つ左にずれています)

読めるシート          : 48
読めるが0行           : 1
停止2枠(今後は無い)   : 3
機側以外のライン      : 6  (--any-sheet で読めます)
その他(対象外のシート): 2
**停止3枠なのに読めない: 0**
```

**ほかのラインのシートは「3枠なのに読めない」に数えません。** VBAも同じ
条件で外すので、様式の問題ではないからです ── 別に数えて、`--any-sheet`
で読めることを添えます。

最後の数が **0 なら、そのまま集計できます**。0でなければ、その行の理由が
出ています。理由は次の5つのどれかです:

| 出る言葉 | 意味 |
|---|---|
| シート名に「_機側」がありません | VBAも同じ条件でシートを選びます。ほかのラインを読むなら「機側以外のシートも読む」 |
| A1が「集計」ではありません(いまは「…」) | 目印の値が違います。**いま何が入っているか**まで出します |
| 停止2枠のブックです(作業時間が AA 列 …) | 枠が1つ少ないテンプレート。読みません |
| 見出しが違います(AG7 は「納入先」のはずが「…」) | どのセルがどう違うかまで出します |
| 拾える行がありません(終了時刻のL列が空…) | **読めたが0行。** VBAも1行も拾いません |

**「読めた」と「拾えた」は別です。** ○ で0行のときも、そう書きます。

## 入れていないもの

- **グラフ**(内訳の円グラフ・PENA割合・EX割合)。VBA側のおまけ機能なので、
  読み取りと転記だけにしています
- **停止2枠(Stop2)のテンプレート**。実物(2026年の機側)は3枠でした
