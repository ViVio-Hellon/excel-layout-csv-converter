# 設計 ── 画面と起動基盤

この文書は**作りの説明**です。使い方は
[はじめに読む_起動と使い方.md](はじめに読む_起動と使い方.md)、
変換そのものの根拠は [../VENDOR.md](../VENDOR.md) を見てください。

構成は社内「汎用Webアプリ作成 基盤仕様書」と、同じ作りの
`python-web-tools`(梱包資材総合ツール)にそろえています ── 起動・停止・
監視の作法を覚え直さずに済むようにするためです。

## 1. 層

```
Start.vbs / start.bat / stop.bat     利用者の入口(通常 / 診断 / 停止)
  └─ start_app.py                    実行環境を整え、起動してよいかを決める
       ├─ launch_guard.py            多重起動の判定(応答で確かめる)
       ├─ server.py                  待ち受けと、受け渡しの形(Request/Response)
       │    └─ boot_server.py        まず待機画面 → 本体へ引き継ぐ
       └─ app/                       画面層
            ├─ __init__.py           組み立てと守り(Host/オリジン/合言葉/占有)
            ├─ shell.py              外枠に渡す値
            ├─ routes/               URLの受付(health / screen / settings / input / job)
            ├─ templates/            base.html + index.html
            └─ static/               tokens/base/layout/components.css, ESモジュール
converter/                           業務と基盤
  app_config.py    アプリ固有値(ID・ポート・上限・ローカル領域)の**唯一の出どころ**
  user_settings.py 設定部の値と、どこを指しているかの確かめ
  screen_lock.py   画面は1枚だけ
  jobs.py          変換の実行・進捗・中止
  intake.py        受け取ったものの置き場所(**タブごとに2つ**)
  idle_exit.py     画面が居なくなったら終わる(**裏のタブ・スリープでは終わらない**)
  awake_clock.py   起きていた時間だけ数える時計(**スリープを無通信に数えない**)
  boot_screen.py   起動待機画面の骨格(標準ライブラリだけ)
  logging_utils.py ログ(launcher / app / **error**。置き場所は設定で変えられる)
  run.py check.py  xlsx → CSV と、シート自身の合計との突き合わせ
  totals.py        シートの合計欄(**空欄と0を区別**)。無いものは比べない
  workday.py       作業日の書き方をそろえる(直したことは必ず出す)
  books.py         1冊の**全シート**を読む(既存の読み手は先頭1枚だけ)
  cells.py         xlsx のセル。**ふりがな(rPh)を値に混ぜない**(読み手は1つ)
  tally.py         機側データ集計(VBAと同じ転記 → CSV 1本。変換が出したCSVも材料に)
  stop_reasons.py  停止内訳(記号→内訳名)。**CSVとマスタ、どちらを読んだか言う**
vendor/                              日報管理ツールの写し。**直しません**
```

**起動基盤は `converter/app_config.py` だけを見ます。** 業務の値
(入力元・出力先・ライン・参照用マスタ・停止内訳CSV)は `user_settings.py`
の担当です ── 配るときに
決まる値と、使う人が決める値を混ぜないための分け方です(基盤仕様書 5.2)。

## 2. 起動(2.1 〜 2.4)

```
Start.vbs ──(pythonw)── start_app.py
                          ├ 実行環境の確認   Python版数 / vendor / config / 書込権限
                          ├ 多重起動の判定   launch_guard.check_existing()
                          ├ ポート束縛       server.AppServer.bind()
                          ├ 待機画面         boot_server.BootApp(同じポートで即出る)
                          ├ ブラウザを開く
                          ├ 準備             写してある日報管理ツールを読む
                          └ 引き継ぎ         Handover.install(app) → ready
```

要点は3つです。

- **待機画面を先に出します。** 時間を食うのは42ファイルの読み込みなので、
  そのあとに待機画面を出しても意味がありません。待ち受けだけ先に始めます
- **開き直しません。** `Handover` が呼び先を1つ持ち、本体ができたら中身を
  差し替えます。開き直すと、その瞬間にブラウザの問い合わせが落ちて
  「接続できません」に見えます
- **秒数で完了扱いにしません。** 待機画面は `/api/health` の `app_id` を
  照合し、`ready` が立ってから切り替えます ── 同じポートを別のアプリが
  使っていても、誤って「起動した」と言わないためです

多重起動の判定は**応答で**行います。目印のファイル
(`runtime/instance.json`)だけでは、強制終了のあとに「起動しているのに
起動していない」が残ります。目印に入れるのは、止めるときに要るもの
(PID・プロセスの起動時刻・合言葉)だけです。

**「起動中」の判断に目印のPIDは使いません。** ポートが受け付けなければ、
その場で目印を消して「空いている」と答えます ── ほかのツールで
「再起動のあとPIDが使い回され、いつまでも起動中と判断して止まる」という
不具合がありました。こちらはそうなりません(`test_launcher.py`)。

**PIDを撃つときだけは、番号では足りません**(1.11.3)。残った目印のPIDを
終了させるのは `stop.bat` と、答えないまま残っていたときの起動です。
再起動のあとは Windows が番号を使い回すので、**番号とプロセスの起動時刻の
両方が合うときだけ**「うちのプロセス」とみなします
(`launch_guard.judge_recorded`)。起動時刻は `ctypes` で OS から読みます
(Windows は `GetProcessTimes`、Linux は `/proc`。追加ライブラリなし)。
前の版が書いた目印には起動時刻が無いので、**「目印を書いた時刻より後に
始まったプロセスは、書いた本人ではない」**で見ます。

| 答え | どうするか |
|---|---|
| 同じ(番号も起動時刻も合う) | 固まっているだけかもしれないので**5秒待ち**、答えなければ終わらせてから起動します |
| 別もの(居ない・起動時刻が合わない) | **撃ちません。** 残っていた目印だけ片付けます |
| 確かめられない(起動時刻が読めない) | これまでどおり(python のプロセスであることだけ確かめます)。確かめられなかったことは言います |

## 3. 画面は1枚だけ

2枚開けると、2つの画面が同じ作業状態を奪い合います。片方で「変換開始」、
もう片方で「中止」。片方で保存した設定を、もう片方は古いまま表示する。
**混乱のもとなので、開くこと自体をお断りします。**

| 段 | どこ | 捕まえるもの |
|---|---|---|
| ① プロセス | `launch_guard.py` | 2つ目のバックエンド |
| ② サーバ | `converter/screen_lock.py` | 別ブラウザ・直接URL |
| ③ ブラウザ | `app/static/js/screen.js` | タブの複製(BroadcastChannel) |

どれか1段では足りません。**複製タブはブラウザ側でしか見分けられず**
(sessionStorage ごと複製されるため)、**別のブラウザはサーバ側でしか
止められない**からです。

**再読込は断りません。** 断ると、読み込みに失敗した画面を開き直せなく
なります。タブは自分の `tab_id` を持ち歩くので、同じタブなら持ち主の
入れ替えとして通します。

閉じた画面は**閉じたときにその場で空きます**(`release` と
`/api/alive {closed:true}`)。覆いが出たときも空けます ── 使わなくなった
画面が占有を抱えたままだと、次の画面を開けるまで待たされます。
どちらも届かなかったとき(ブラウザが落ちた、端末が切れた)の保険として、
`screen_timeout_seconds`(既定12秒)で空きます ── 二度と開けない状態を
作らないためです。

**裏に回ったタブは、戻ったときに黙って取り直します**(`screen.js` の
`regain`)。ブラウザは隠れたタブのタイマーを間引き(Chrome は1分に1回ほど)、
数分で凍結するので、生存確認が途切れて占有が期限切れになります。戻った
ときに「使えなくなりました」と出ていたのがこれです ── 利用者の言葉で
「裏に回って復帰させると停止している(触ると戻るが)」。**誰も使って
いないなら断る理由がありません。** ほかの画面が持っていれば取り直せない
ので、「画面は1枚」は変わりません。

期限を延ばして守る手もありますが、延ばすと**ブラウザが落ちたあと次を
開けるまで同じだけ待たされます**(覆いの文言も「12秒ほどで開けます」と
約束しています)。取り直すほうが、どちらも待たせずに済みます。

## 4. 守り(`app/__init__.py`)

| | 何を防ぐか |
|---|---|
| Host の確認 | 外のドメインを `127.0.0.1` に向ける手口 |
| `Sec-Fetch-Site` | 別のページからの書き込み |
| 起動トークン | 同じPCの別プロセス・利用者が開いた別のサイト |
| 画面の占有 | 2枚目の画面からの操作 |

`/api/health` と `/api/alive` はトークンを要求しません。前者は**まだ
トークンを知らない相手**(多重起動の判定・待機画面)が正当に問い合わせる
ため、後者は**トークンが切れた画面を黙って死んだ扱いにしない**ためです。
どちらも返すのは状態だけで、業務データを含みません。

**停止だけは合言葉では通しません。** 起動トークンは画面のHTMLに入るので、
**断られた2枚目のタブも持っています。** それで止められると、ちゃんと開いて
いる画面の作業を、居ないはずのタブが落とせてしまいます。止めてよいのは
次の2つだけです。

| 誰が | 何を持っているか |
|---|---|
| いま使っている画面 | 持ち主の `X-Screen-Id` |
| 同じ端末の `stop.bat` | `runtime/instance.json` の `stop_key`(**画面には渡りません**) |

`stop_key` はローカル領域の中にしかないので、ブラウザからは読めません。

## 5. API

| | |
|---|---|
| `GET /` | 準備中は待機画面、終わればアプリ画面 |
| `GET /api/health` | 起動確認(**トークン不要**) |
| `POST /api/alive` | 心拍(**トークン不要**。返すのは状態だけ)。本文に `tab` / `page` / `state`(`visible`・`hidden`)/ `leaving` ── **裏に回ったタブを死んだ扱いにしない**ため |
| `POST /api/shutdown` | 停止(実行中は確かめてから)。**待機画面も答えます** ── 本体を組み立てられなかったときに止められないと、Python が残ってフォルダを消せません |
| `GET /api/diagnostics` | 調べるときの1枚 |
| `POST /api/screen/claim` `release` | 画面の受け取りと返却 |
| `GET/POST /api/settings` | 設定部 |
| `POST /api/job/start` | `tab` で振り分け(`convert` / `tally`) |
| `POST /api/open` | 出力先・ログを開く(**知っている場所だけ**) |
| `GET /api/input`, `scan` `begin` `add` `clear` | 読ませるブック |
| `POST /api/job/start` `cancel`, `GET /api/job` | 変換 |

断りは `{"ok": false, "reason", "detail"}` の形で返します。**文言はサーバが
持ちます** ── 画面が組み立てると、同じことを2か所で決めることになります。

## 5.5 画面のタブ

設定部は共通で、その下を2つに分けています。**画面は1枚のまま**です。

| タブ | 受けるもの | 出すもの |
|---|---|---|
| 変換 | .xlsx / .xlsm(ドラッグ or 入力フォルダ) | 1日・1ラインごとに4本組CSV |
| 機側データ集計 | .xlsx / .xlsm / .csv(ドラッグ) | VBAと同じ転記を1本のCSV |

受け取り置き場は `work/intake/convert` と `work/intake/tally` に分かれます
── 片方を片づけたときにもう片方まで消えると、「入れたはずのものが無い」に
なります。

**進捗と結果は1か所**です。走る仕事は一度に1つ(`jobs.Runner`)なので、
どちらのタブから始めても同じ場所に出ます。表の見出しは仕事の種類で変えます。

## 6. 長時間処理(監視レベル2)

- 進捗はプロセス側(`converter/jobs.py`)が持ちます。開き直しても、別の
  タイミングで見ても同じものが見えます
- **中止できるのは読み取り中だけ**です。CSVを書き始めてからは止めません
  ── 4本組を半分書いた状態で残すほうが危ないからです
- ブラウザを閉じても変換は続きます。終わって誰も見ていなければ、
  `converter/idle_exit.py` がバックエンドを終わらせます(**処理中は
  終わりません**)
- **裏に回ったタブとスリープでは終わりません**(1.11.0)。ブラウザは
  見えていないタブのタイマーを間引く・止めるので、隠れる瞬間の合図を
  受けて「心拍が無くても居る」とみなします。時刻はスリープを数えない
  時計(`converter/awake_clock.py`)で見るので、復帰の瞬間に落ちません
  ── 画面の占有(`screen_lock`)も同じ時計です

## 6.5 共有フォルダとDBの扱い

このツールが触るDBは2つだけで、**どちらも書きません**。

| | 何を | どう扱うか |
|---|---|---|
| 使い捨てSQLite | 変換の途中の明細と集計 | `%TEMP%` に1回ごとに作り、終われば**丸ごと捨てる**。同時に触るのは自分だけ |
| 参照用マスタ | 停止内訳の名前 | **共有のファイルは開きません。** 手元(`cache`)へ写してから、読み取り専用で開きます |

**共有のsqlite3を開かないのが要点**です(`vendor/nippou/source_db.py`)。
読み取りで開いてもSQLiteはロックを取り、`-wal` / `-shm` / `-journal` を
触ります。上流が `pending_….sqlite3` へ書いてから置き換える運用なので、
こちらが開いていると**置き換えが失敗して取り残されます**。写しなら、相手に
対しては「読む」以上のことをしません。

- 写し直すかは**大きさと更新時刻だけ**で決めます(`stat`。開きません)
- 写したあと `PRAGMA quick_check`。破れていれば少し待って3回まで写し直し、
  それでも駄目なら**読めないと言います**(欠けた中身を黙って使わない)
- 開くのは写しのほうで、`query_only` と `busy_timeout=10秒`

**参照用マスタが `.accdb` のときは Access の経路になります**
(`cscript.exe` + ADODB、または ODBC)。共有に `.laccdb` が作られ、ACE が
必要です。同じフォルダに `伝送用ファイル.sqlite3` があればそちらを優先します。

【出力先が共有のとき】
CSVは**同じフォルダに仮の名前で書いてから置き換えます**。書いている途中で
失敗しても、前に出したCSVはそのまま残ります(`converter/tally.py`)。ただし
**別のPCが同じ名前へ同時に書けば、あとに置き換えたほうが残ります** ──
取り違えを避けるなら、出力先はPCごと(または担当ごと)に分けてください。

## 7. 置き場所(2.7 / 4.6)

アプリ本体へは**何も書きません**。共有フォルダに置かれることがあるので、
ログやキャッシュを書くと利用者どうしでぶつかります。

```
%LOCALAPPDATA%\ExcelCsvConverter\
  runtime\  instance.json(PID・**プロセスの起動時刻**・ポート・合言葉)
  logs\     <ツール名>_launcher.log / _app.log / _error.log
  pycache\  読込キャッシュ
  cache\    取り直せるもの
  work\     intake\(ドラッグで受け取ったブック。使い終われば消す)
  backup\   復旧目的で残すもの
  data\     settings.json(**消してはいけないもの**)
```

設定の「ログの置き場所」で共有へ集めるときは、**指した先にツール名の
フォルダを作り、ファイル名もツール名から始めます**
(`\\共有\ログ\ExcelCsvConverter\ExcelCsvConverter_app.log`)。
共有の掃き出し先は何本ものツールで共用されるので、**フォルダだけでも
名前だけでも足りません** ── 1本取り出した時点で、開かずに分かる必要が
あります。名前の作り方は `converter/logging_utils.file_name()` の1か所、
ツール名は `config/app.json` の `log_name` です。

## 8. 試験

```bash
python -m unittest discover -s tests -t .
```

`-t .` を付けるのは `tests/__init__.py` を読ませるためです。読まれないと
**本番の記録に書き込みます**(`tests/_isolation.py` が最後の砦)。

| ファイル | 見ているもの |
|---|---|
| `test_convert.py` | 変換(読めること・数が合うこと・同じCSVが出ること) |
| `test_tally.py` | 機側データ集計(拾う行・埋め方の順序・見出し・断り方) |
| `test_app_config.py` | アプリ固有値。壊れていても起動できること |
| `test_screen_lock.py` | 2枚目を断る／再読込は断らない／心拍が占有を延ばす |
| `test_security.py` | Host・合言葉・別ページからの書き込み |
| `test_web_settings.py` `test_web_input.py` `test_web_job.py` | 画面からの操作 |
| `test_launcher.py` | 実行環境の確認と多重起動の判定 |
| `test_boot_and_exit.py` | 待機画面・引き継ぎ・停止・自動終了・**スリープ復帰**(`awake_clock`) |
| `test_launch_files.py` | `.vbs` / `.bat` の文字コードと改行 |
| `test_isolation.py` | 試験が本番の記録を汚さないこと |
