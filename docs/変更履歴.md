# 変更履歴

版は `config/app.json` の `version` ただ1つが出どころです(帯のバッジ・
`/api/health`・診断情報がすべてここを読みます)。**メジャー.マイナー.
パッチの数字3つ**だけにします ── 端末はフォルダごとコピーして配るので、
「いまどれが入っているか」を聞かれたときに並べて比べられる番号が要ります。

| 上げるところ | いつ |
|---|---|
| メジャー | 配り方や使い方が変わり、手順書を読み直してもらう必要があるとき |
| マイナー | 画面や機能が増えたとき、構成を組み替えたとき |
| パッチ | 不具合を直したとき |

## 1.15.2

**「中身が古いままです」の札に、新しい中身がどこにあるかを出します。**

展開し直しても直らない、の原因はほとんどが**入れ子**です。Windows の
「すべて展開」は、すでに同じ名前のフォルダがあるところへ展開すると

    …\excel-layout-csv-converter-main\excel-layout-csv-converter-main\

のように1つ下へ入ります。exe は**自分と同じ階層**の `bridge.py` を使う
ので、新しい中身が1つ下に入ったまま、古い中身で動きます。

札がこう出るようになりました。

    窓(exe)は VER1.15.2、中身は VER1.12.0(置いたのは 2026-11-08)です
    ── このフォルダの中身が古いままです。新しい中身(VER1.15.2)は、
    この中の「excel-layout-csv-converter-main」に入っています ──
    そのフォルダの中身を1つ上へ移すか、exe をそちらへ入れて使って
    ください(…)。

入れ子が無いときは、中身を置いた日付を添えて、フォルダごと入れ替えて
ほしいと言います(日付を見れば、入れ替えたつもりのフォルダが古いまま
かどうか分かります)。

## 1.15.1

**共有(UNC)の道にある日報データを開けなかったのを直しました。**

    共有の日報データ(日報データ.sqlite3)を読めなかったので、
    集計明細CSVと紙で探しました
    パスも設定してあり検索できるはずだが?

`\\サーバ\共有\日報データ.sqlite3` を `file://サーバ/…` にすると、
sqlite3 は **`サーバ` を URI の宛先(authority)**と読み、

    OperationalError: invalid uri authority: サーバ

で開けませんでした。**斜線を4本**にして宛先を空にします
(`file:////サーバ/共有/…`)。記号(`?` `#` 空白)と漢字は百分率で
書き換えます ── 道に `?` があると、そこから先が「開き方の指定」と
読まれてしまいます。

### 読めているかどうかを、探す前に出します

板集計タブの頭に出しました。

    共有の日報データ: 読めます ── \\サーバ\…\日報データ.sqlite3(ライン: L-1・L-2)
    共有の日報データ: …がまだ無いので \\サーバ\…

「設定したのに読めていない」を、探してから気づくのでは遅いためです。
読めなかったときの断りにも、**元の言葉**(`invalid uri authority: …` など)
を添えるようにしました ── 「読めなかった」だけでは、道が違うのか形が
違うのかが分かりません。

ここを見るのは画面を出すたびなので、待ち時間は探すとき(8秒)より短く
**3秒**で見切ります(届かない共有で毎回待たないように)。

### 「中身が古いままです」の知らせに、どのフォルダかを入れました

    窓(exe)は VER1.15.0、中身は VER1.12.0 です ──
    このフォルダの中身(画面と変換のファイル)が古いままです。
    C:\…\excel-layout-csv-converter-main を、配られたフォルダ
    (ExcelCsvConverter-windows-<版>)でまるごと入れ替えてください
    (exe だけを入れ替えても中身は新しくなりません)。

## 1.15.0

**共有の日報データを直接読めるようにしました。** 現場からの問いです。

    all-tools は共有の日報そのものを読む: LocalBackup のことでしょうか?
    参照パス設定できるようにして同じものを見たほうがいいのではないですか?

**控え(LocalBackup)ではありません。** 向こうが読んでいるのは共有の
`日報データ.sqlite3`(各端末が「共有へ保存」で送る先。
`T_日報ヘッダー_<ライン>` / `T_日報明細_<ライン>`)です。控えはその端末の
中の写しで、ほかの端末の行は入っていません。

**そして、指すようにしたほうがよい** ── ご指摘のとおりでした。設定タブに
**「共有の日報データ」**を足し、ロットを探すがまずそこを読みます。

### 探すところは3つ(上から強い順)

| 出どころ | 何が入っているか |
|---|---|
| **共有の日報データ** | 全ライン・全端末。向こうの「ロットを探す」と**同じ範囲** |
| 集計明細CSV | 参照パスの `<ライン>\集計\…`。集計から除いたページは入っていません |
| 紙(印刷用HTML) | 参照パスの `<ライン>\印刷\…`。集計に無いページを補います |

上の出どころが持っているページは、下では読みません(同じ行を二重に
出さないため)。表の「**どこから**」の列と、「**探した範囲**」の一行に
出します。

### 決まり

- **読むだけ**です(`?mode=ro`)。無いファイルを作らず、書けません
- **待たせません** ── 開くのも問い合わせも合わせて8秒で見切り、当たった
  行は2000行で止めます(共有に届かないときは、確かめるだけで何十秒も
  止まることがあります)
- **読めなくても探すのをやめません。** 理由を画面に出して、集計明細CSVと
  紙で続けます(向こうも読めないときは手元で続けます)
- **Access(.accdb)は読みません** ── ロット№の比べ方(全角・小文字を
  揃えてから頭を比べる)は Access の SQL では書けず、表を丸ごと書き出す
  ことになります。向こうも同じ線引きです
- ページの列は `頁` でも `ページ` でも読みます(VBA が作った表と、途中の
  版が作った表で字が違います)
- 配布設定でも配れます

本物のブラウザで確認: 集計から除いた作業者のページ(2ページ目)が
「共有の日報」として出て、集計に入っている1ページ目は「集計明細」から
出る ── 二重にはなりません。

## 1.14.1

**「集計から除く」で外した作業者のロットも探せるようにしました。**
現場からの指摘です。

    all-tools に「集計から除く」があり、指定した作業者のデータを集計に
    入れないようにできます。本ツールはそのデータから LOTNO 検索している
    ので、除外されて作成されたデータでは検索できない LOT があることに
    なります

**そのとおりでした。** 向こうで外れるのは集計を作るところ
(`services/agg_exclude` → `summary.refresh_shift`)なので、そこから書く
**集計CSV・集計明細CSV・停止内訳CSVの3本とも**から、そのページが消えます。
1.14.0 のロット検索は集計明細CSVだけを読んでいたので、**除かれたロットは
出ませんでした**。

### 紙(印刷用HTML)から拾います

ページそのものは消えず、**同じ参照パスに紙が残っています**
(`<ライン>\印刷\2026.11\17\印刷_2026年11月17日_L-1_1直_2.html`)。
除いたページの紙には「**自動**」の印が付きます(時間を自動で割り振って
いるため)。そこで、**集計明細に無かったページの紙だけ**を開いて補います。

- ファイル名に日付・ライン・直・ページが入っているので、**開く前に**
  「集計明細にあるページか」が分かります ── 除外が無ければ**1枚も
  開きません**
- 表に「**どこから**」の列を足しました:`集計明細` /
  `印刷(集計から除く)` / `印刷(集計に無い)`
- 紙には**用途名・納入先・作業時間の欄がありません**(紙の印刷範囲の外)。
  空のまま出します ── 無い欄を埋めるより、無いと分かるほうが親切です
- 紙は**共有へ保存したとき・印刷したとき**に書かれます。どちらもして
  いないページは参照パスに無いので出ません(向こうの「ロットを探す」は
  共有の日報そのものを読むので、そこだけは範囲が広いままです)

読み手(`converter/plate_paper.py`)は標準ライブラリの `html.parser` だけで
書いてあります。欄の名前は**紙の見出しから組み立てる**ので
(`梱包作業時間 開始 時`)、集計明細CSVと同じ字になり、列が増えても
位置ではなく名前で拾えます。試験には**向こうが出した本物の紙**を
置いてあります(`tests/_paper_sample.py`)── 自分で組み立てた形を自分で
読んでも、向こうが変わったことに気づけません。

## 1.14.0

**板集計タブに「ロットを探す」を足しました。** 日報管理ツール(all-tools)の
同じ機能の移植です。

    期間を絞ってロットNo検索したい場合に何を検索したらいいですか?

専用の探し方が無いと、年月のフォルダ → 日のフォルダ → CSV を開いて
Ctrl+F、を日数ぶん繰り返すことになります。**期間とロット№を入れて1回**で
出します。

| 欄 | |
|---|---|
| **開始日・終了日** | 必須。はじめは板集計と同じ期間が入っています |
| **ロット№** | 必須。**前方一致**。`ｎ７１` でも ` n71 ` でも `N7131T0` に当たります |
| **ライン** | 「全ライン」か、参照パス配下のライン1つ |
| **探す** | 画面に出すだけ(**読むだけ**で何も書きません) |
| **CSVに出す** | 出力先フォルダへ(**画面と同じ行**。1行目に探した条件) |

読むのは **集計明細CSV** です ── 1行=1ロットで、紙の欄がそのまま
入っています(集計CSVは直ごとの合計なので、ロットの行がありません)。
出る列は 作業日・ライン・直・ページ・行・ロット№・材・調質・厚×幅×丈・
検入枚数・開始・終了・実績枚数・実績重量・作業時間(分)・作業者・
用途名・納入先。

**空欄は断ります**(期間の全部を出しても上限に当たるだけ)。並びは
作業日 → ライン → 直 → ページ → 行。画面は200行までで、超えたら
先の200行だけ出して「桁を増やすか期間を絞ってください」と言います。

### 直したもの ── はじめのタブで一覧が空だった

1.13.2 ではじめに出すタブを板集計にしたとき、**タブを一度も押さないと
ラインの一覧も期間も空のまま**でした。`tabs.wire()`(いまのタブを
知らせる)を画面を組む前に呼んでいたので、**誰も聞いていないうちに
知らせが飛んで**いたためです。タブの配線をいちばん最後にしました
(試験でも並びを見ます)。

## 1.13.1

**板集計の Excel を、VBAが出していた月別集計のブックに合わせました。**
現場から出た指摘は3つで、どれも**集計シートの形**から来ていました。

| 言われたこと | 何が起きていたか |
|---|---|
| 稼働率と生産性のスケールが合っていない(生産性が折れ線に見えない) | 90 と 3 を同じ目盛りに乗せていました。**別のグラフ**に分けました |
| 直別の重量・枚数が直別になっていない | 集計シートが**1行=1直**だったので、系列を直ごとに分けられませんでした |
| 停止の分類は円グラフにしてほしい | 棒で出していました。**円**にしました(分類の数だけ) |

### 集計シートを「1行=1日・直は列」にしました

向こうのブックと同じ形です。

```
日付 / 合計(枚) / 合計(t) / 1直合計(枚) / 1直合計(t) / 2直… / 3直… /
作業時間合計(分) / 稼働時間合計(分) / 管理ロス停止(分) / 突発停止(分) /
ﾊﾝﾄﾞﾘﾝｸﾞ停止(分) / その他停止(分) / 停止合計(分) / 稼働率(％) /
生産性1直(t/h) / 生産性2直… / 日毎累計(枚) / 日毎累計(t)
```

直を**行ではなく列**に置いたので、グラフの系列が直ごとに分かれます。
ラインを2つ以上選んだときは「1行 = 1日 × 1ライン」にして、ライン名の
列を足します(累計もラインごとに積みます)。

CSVで出すのと同じ行(直ごと)は「**元データ**」シートに残します ──
数が合わないときに、どこで変わったのかを追えるように。

### グラフ

| | |
|---|---|
| 直重量(t) ／ 直枚数(枚) ／ 生産性(t/h) | 棒。**直ごとに系列を分ける** |
| 停止・稼働時間(分) | 棒。作業・稼働と停止の分類 |
| 稼働率(％) ／ 累積枚数(枚) | 折れ線(**稼働率は単独**) |
| 直枚数・累積枚数推移 | 棒 + 折れ線。**累積は右の目盛り**(第2軸) |
| 「(分類)」(分) | **円**。分類の数だけ |

### 棒が白かったのを直しました

**系列の色を自分で指すようにしました。** Excel の既定の色は「テーマの色」
から来るので、テーマ(`xl/theme/theme1.xml`)を入れていないブックでは
色が決まらず、**棒も扇も白く塗られて見えません**。LibreOffice で開いて、
軸と凡例だけが出て中身が空なことで分かりました ── 試験は XML の形しか
見ていなかったので、通ったまま見逃していました。

テーマ一式(8KB)を抱えるより、使う色をこちらで指すほうが短く、
**画面のグラフと同じ色**にできます。直の4色は Excel のグラフと同じ
青・赤・緑・紫です。

試験 394件(13件増)。書き出した `.xlsx` は **LibreOffice で開いて
絵になるところまで**見ています(Excel 本体での見え方は Windows で)。

## 1.13.0

**板集計タブを増やしました。** あわせて**設定をタブに移し**、
**配布設定**を足しました。

| | |
|---|---|
| [板集計.md](板集計.md) | 日ごとのCSVを期間ぶん1つにまとめ、グラフにして CSV / Excel へ |
| [配布設定.md](配布設定.md) | 1台で決めた設定を、配った先の端末でそのまま使う |

### 板集計

日報管理ツール(all-tools)が**日ごと・ラインごと**に書いたCSVを、
期間とラインを指して**1本**にまとめます。参照パス配下の形は向こうの
ままです ── このツールの変換タブが出す4本組も同じ形なので、どちらも
読めます。

```
<板データ参照パス>\L-1\集計\2026.11\17\集計_2026-11-17_L-1.csv
                                           停止内訳_2026-11-17_L-1.csv
```

- 参照パス直下の**ラインを一覧**に出し、選んだラインだけを集計します
  (**複数選べます** ── ライン別に色を分けて並べて比べられます)
- **グラフは画面でも見られます**(日別の推移・直別・停止の輪・表)。
  日報管理ツールの集計画面からの移植で、**追加ライブラリは使いません**
  (SVGを自分で組み立てます)
- **Excel はグラフ付き**です。画像ではなく**本物のグラフ**で、集計
  シートのセルを指しています ── 受け取った人が期間を絞ったり系列を
  足したりできます。`.xlsx` は標準ライブラリだけで組み立てます
  (`converter/xlsx_out.py`)
- **CSVのときグラフは付きません**(表だけの形です)

決まりごとを3つ:

| | |
|---|---|
| 列は**名前で読みます** | all-tools は列を足します(`その他(分)`)。位置で読むと足された日から静かに1列ずれます。知らない列は捨てずに後ろへ付けて出します |
| 稼働率は**出し直します** | 直ごとの平均にすると、1直だけ動いた日と3直とも動いた日が同じ数字になります |
| 読めなかったものは**黙って捨てません** | CSVが無い・見出しが違う日は、理由を数えて画面とExcelに出します |

歯止めは一度に400日まで。ラインは**一覧にあるものだけ**受けます
(画面から来た字をそのまま使うと、参照パスの外を読ませられます)。

### 設定をタブにしました

前は画面の上に固定していたので、**開くたびに設定が最初に目に入り**、
やることの画面が下へ送られていました。設定を触るのは据え付けのときと
置き場所が変わったときだけです。

    変換 ／ 機側データ集計 ／ 板集計 ／ 設定

- **パスの欄は横いっぱい**にしました。共有の道は長く、2列に並べると
  先が見えません(見えない道は直せません)
- 板集計・設定のタブでは進捗と結果を隠します。**走っている間は
  どのタブでも出します**(変換を始めてから設定を見ても、進み具合が
  見えなくならないように)

### 配布設定

設定は端末ごとのローカル領域に入るので、ツールのフォルダをコピーしても
付いて行きません。1台で決めて書き出し、**フォルダごと配る**と、配った
先が起動のときに読み込みます。

**上書きしません** ── その端末でまだ決まっていない項目だけを埋めます
(空は「無い」と数えます)。前に配った値のままなら、配り直した新しい値に
置き換えます。揃えたいときは「読み込み直す」。

配布設定から入った値には、設定タブで「**配布設定の値**」の札が出ます。

### 中で変わったもの

## 1.11.3

**ほかのツールの「残ったPIDファイル」の不具合を、こちらでも確かめました。**
報告は4つでした。**2つは当てはまらず、1つは当てはまり、1つは念のため
直しました。**

| 報告 | こちらは |
|---|---|
| PIDファイルのPIDが生きていれば「起動中」と判断する | **当てはまりません。** 判定は**応答**です(ポート + `/api/health` の `app_id`)。ポートが受け付けなければ、残っていた目印はその場で消して「空いている」と答えます |
| 再起動後のPIDの使い回しで、いつまでも「起動中」になる | **当てはまりません**(上と同じ理由。実際に、生きている別プロセスのPIDを書いた目印を置いて確かめました → `free`、目印は片付く) |
| `stop.bat` が「接続できない」で終わり、ファイルを消さない | **消していました**が、**言い方を直しました**(下記) |
| 残ったPIDを撃つときに、番号の使い回しを見分けていない | **当てはまりました。** 直しました(下記) |

### 当てはまった1つ ── PIDを撃つ道

残った目印のPIDを**終了させる**のは `stop.bat`(答えないとき)と、
正常終了を頼んでも応答が無いときです。そこでの確かめが
「`python.exe` かどうか」だけだったので、**再起動のあとに同じ番号を持った
別の Python を終わらせてしまう**余地がありました。

- 目印に**プロセスの起動時刻**を書くようにしました(`proc_started_at`)。
  OSから `ctypes` で読みます(Windows は `GetProcessTimes`、Linux は
  `/proc`)── **追加ライブラリはありません**
- **番号と起動時刻の両方が合うときだけ**「うちのプロセス」とみなします
  (`launch_guard.judge_recorded`)。合わなければ**撃たず**、残っていた
  目印をその場で片付けます
- **前の版が書いた目印**には起動時刻が入っていません。そのときは
  **「目印を書いた時刻より後に始まったプロセスは、書いた本人ではない」**
  で見ます(報告と同じ考え方です)
- 起動時刻が読めない端末では、これまでどおり(`python.exe` の確かめだけ)に
  なります。**確かめられなかったことは言います**

### 答えないまま残っていたときの起動(新しく)

ポートは握られているのに `/api/health` が答えないとき、これまでは
「stop.bat を実行してから起動し直してください」と断っていました。いまは:

- 控えの**番号と起動時刻が合う**(前回のうちが固まっている)
  → **5秒待ち**、それでも答えなければ**終わらせてから起動します**
- **合わない**(番号の使い回し)→ 触りません。残っていた**目印だけ片付け**、
  ポートは別のプログラムだと言います
- **確かめられない** → これまでどおり断ります

### `stop.bat` の言い方

目印が残っていたときは
**「起動していません。残っていた目印を片付けました ── Start.vbs で
起動できます」**と出します(前は「止めるものはありません」だけでした)。
`--status` には、控えのPIDが**本人かどうか**も出します。

### なぜこちらでも起きやすいのか

1.11.0 で**裏に回したタブでは終わらない**ようにしたので(最大7日)、
「ツールが動いたまま PC を終了・再起動する」は増えます ── 報告と同じ
前提です。目印が残りやすい側に回ったので、撃つ道の見分けを足しました。

### 確かめたこと

| 試したこと | 結果 |
|---|---|
| 再起動後の目印だけ(ポートは空き) | `free` ── 目印は片付き、普通に起動できる |
| そのとき `stop.bat` | 「残っていた目印を片付けました ── Start.vbs で起動できます」/ 戻り値 0 |
| ポートは答えない + PIDが使い回された別もの | **撃たない**(`taskkill` を呼ばない)。目印を片付け、ポートは別のプログラムだと言う / 戻り値 1 |
| ポートは答えない + 本人(番号も起動時刻も合う) | 5秒待ち、答えなければ終わらせて起動を続ける |
| 起動時刻が読めない | 触らない(手がかりの目印も残す) |

試験 272件すべて通過(8件足しました)。

**共有へ集めたログが、どのツールのものか分かりませんでした。** 現場の

```
        ExcelCsvConverter_app.log        筋道
        ExcelCsvConverter_error.log      うまくいかなかったことだけ
        ExcelCsvConverter_launcher.log   起動
    dbviewer\ …                         ← ほかのツールのぶん
```

- 設定部の案内は**実際に書いている場所**(ツール名の中)を出します。
  「ログを開く」もそこを開きます

名前を変える前に出した `app.log` などは**そのまま残します** ── 共有には
ほかのツールのファイルもあるので、こちらから触りません(不要なら手で

## 1.9.2

**起動に失敗すると、止められないまま残っていました。** 日報管理ツール
(all-tools)で見つかった不具合の報告を受け、**こちらにも同じ道があるかを
確かめ、ありました。** 直しました。

### 起きる条件(2つ重なったときだけ)

1. 起動の途中で**本体を組み立てられない**(フォルダの一部が欠けた・設定
   ファイルが壊れた・必要な部品が無い、など)
2. そのあと `stop.bat` で止めようとする

ふだん正常に起動しているぶんには起きません。

### 何が起きていたか

本体を組み立てられなかったとき、このツールは**待機画面に理由を出した
まま残ります**(理由を読めるようにするため、わざとそうしています)。
ところが**その待機画面が、止める合図に答えていませんでした**:

```
POST /api/shutdown → 503 {"ok": false, "reason": "起動しています"}
```

`stop.bat` も `--force` も通らず、20秒待ってPIDを撃つ道へ落ちます。
さらに `stop.bat` の中身には、**確かめずに成功と言う**道が残っていま
した ── ポートは使われているのに `/api/health` が答えないとき
(起動の途中で固まったとき)は「触りません」と言って**0を返し、
PIDの控え(`runtime/instance.json`)まで消して**いました。

その結果、Python が残り、**そのフォルダを消せません**(配り直しは
フォルダの置き換えなので、ここで詰まります)。

### 直したこと

- **待機画面も `POST /api/shutdown` に答えます**(`boot_server.BootApp`)。
  通すのは停止の合図(`stop_key`)を持ってきた相手だけ ── 本体と同じ鍵で、
  起動トークンでは通しません。本体が無いので実行中の確認は要りません
- **止められる状態を、待ち受けを始める前に作ります**
  (`boot.shutdown_hook = srv.request_stop`)
- **理由の知らせを別の糸で出します。** Windows の MessageBox は押される
  まで戻らないので、本体の糸で出すと「止めてと言われても、誰かがOKを
  押すまで終われない」プロセスになります
- **10分で自分から閉じます**(`FAILED_BOOT_LIMIT_SEC`)。読む時間は置き
  ますが、置き去りにされたら片づきます
- **`stop.bat` は確かめてから言います**(`process_manager`)
  - 残っていれば「まだ残っています(PID …)」と出し、**終了コードも0に
    しません**
  - 答えないときも「触りません」で終わらせず、**控えていたPIDの道**へ
    進みます
  - **止まったと確かめるまで目印を消しません** ── 消すとPIDの控えが
    無くなり、次に打っても手がかりがありません
  - `--status` に「まだ準備できていません」と**起動の失敗の理由**を出します

### 確かめたこと

- わざと組み立てに失敗させたプロセス(`start_app` の本当の道)を、
  `stop.bat` と同じ呼び方で止められました ── 終了コード 1(起動の失敗)、
  **プロセスは残らず、目印も片づきます**
- 直す前の待機画面に戻すと、同じ試しで**止まりませんでした**
  (`503` → PIDの道 → 残る)。試験もその形で落ちることを確かめました
- ポートは答えるのに health が答えない状態で `stop.bat` を打つと、
  **0を返さず、目印も残ります**
- 試験 234件すべて通過(9件足しました)
