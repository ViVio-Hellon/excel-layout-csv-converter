# 変更履歴

版は `config/app.json` の `version` ただ1つが出どころです(帯のバッジ・
`/api/health`・診断情報がすべてここを読みます)。**メジャー.マイナー.
パッチの数字3つ**だけにします ── 端末はフォルダごとコピーして配るので、
「いまどれが入っているか」を聞かれたときに並べて比べられる番号が要ります。

| 上げるところ | いつ |
|---|---|
| メジャー | 配り方や使い方が変わり、手順書を読み直してもらう必要があるとき |
| マイナー | 画面や機能が増えたとき、構成を組み替えたとき |
| パッチ | 不具合を直したとき |

## 1.8.0

**同じシートなら、ブックから集計してもCSVから集計しても同じ結果になります。**
利用者の言葉で「シートA→CSVA これでAの結果が変わるのは使用できない」。

### 何が起きていたか

シートは停止を**2か所**に書いています。

```
S・U・W列  作業停止内訳-1/2/3   「材料待ち」などの内訳名 + 時間   ← VBAの機側データ集計が読む
AJ〜AO列   作業停止①②③        記号(ヲ・0・E…) + 時間          ← 日報管理ツールが読む
```

変換が出す4本組は**日報管理ツールと1バイトも違わないもの**なので、停止は
記号しか持っていません。そのため「ブックから集計(内訳側)」と「変換CSVから
集計(記号側)」で答えが変わっていました。

### 直したこと

- 変換のときに、**5本目**として機側データ集計の材料
  (`機側データ集計_<ライン>_<日付>.csv`)を同じ日付フォルダへ出します。
  **シートから直に拾ったもの**なので、あとでCSVから集計しても
  **1行1列までブックと同じ**です(4本組には手を入れていません)
- 集計タブは**同じ日・同じラインを2回積みません**。材料と集計明細が
  両方入っていても、**元に近いほう**だけ使います
  (ブック > 材料・前に出した集計 > 集計明細)。飛ばしたほうは理由を出します
- 読む順は渡された順のまま、間引きは**読み終えてから**決めます ── どれが
  元に近いかは、全部読まないと決まらないので
- 材料が拾えないシート(停止2枠など)でも変換は止まりません。5本目が
  出ないだけです

### 確かめたこと

実物2冊で、**ブックから集計 ⇄ 日付フォルダから集計**が完全一致:

| | ブックから | 日付フォルダから |
|---|---|---|
| 機側 2025.07.15 | 32行 / 停止830分 | **32行 / 830分(1行1列まで同じ)** |
| 板 2026.08.26 | 21行 / 停止500分 | **21行 / 500分(同上)** |

### シート側の食い違いについて(直していません)

2か所に書かれた停止は、**同じ直の合計で突き合わせると揃います**:

| | 内訳側(S/U/W) | 記号側(AJ/AL/AN) |
|---|---|---|
| 板 2026.08.26 1直/2直/3直 | 140 / 150 / 210分 | 140 / 150 / 210分(全一致) |
| 機側 2025.07.15 2直/3直 | 545 / 125分 | 545 / 125分(一致) |
| 機側 2025.07.15 **1直** | **160分** | **200分(40分ちがう)** |

揃わないのは機側の1直だけで、**打ち間違いの疑い**です(行32: 内訳
「データー入力」20分 / 記号 Ｂ・Ⅾ・E で60分)。どちらが正しいかは現場に
しか分からないので、**こちらでは寄せていません**。見つけて出すことは
できます(ご相談)。

## 1.7.0

**板とコイルで、機側データ集計の列を分けました。** 利用者の言葉で
「板のCSVにだけ合紙・ＶＣ種別を足す / 板、コイルで集計が違うので分けて
ください」。

```
コイル(機側 / LS)  日付 … 作業人数, 縦割, 横割, 係数処理ﾛｯﾄ数   23列(VBAのまま)
板(そのほか)       日付 … 作業人数, 合紙, ＶＣ種別              22列
```

- **先頭20列(日付＋共通19項目)は同じ位置**です ── 並べて見てもずれません
- 合紙(O)・ＶＣ種別(R)は**VBAの転記列に入っていません**。機側では使わない
  欄なので、機側ライン用のマクロには要らなかったものです。板の集計には
  要るので足しました
- 埋め方も合わせました。合紙とＶＣ種別は**ロット単位**で埋めます
  (etc・包装仕様NO と同じ ── どちらもロットに付く値なので)
- **どのラインをコイルとみなすか**は `config/app.json` の `lines.coil`
  (既定 `["LS"]`)。ここに無いラインは板あつかいです ── 現場で変わる値なので、
  コードではなく設定に置いてあります
- 前に出した集計CSVを積み増すときは、**並びが違えばそのラインの並びへ
  移します**(縦割・横割・係数処理ﾛｯﾄ数 ↔ 合紙・ＶＣ種別。相手に無い欄は空)
  ── 1本のCSVの中で列の数が揃っていないと、開いたときに読めません

実物で確かめました: 機側5冊 + 板1冊 →
`機側データ集計_LS_…csv`(210行 / 23列 / 縦割・横割・係数が入る) と
`機側データ集計_HVC_…csv`(21行 / 22列 / 合紙15行・ＶＣ種別21行が入る)。

## 1.6.0

**機側以外のシートも集計に入れられるようにしました(頼まれたときだけ)。**
集計が「拾える行がありませんでした」で終わるのは、VBAが**機側のシートしか
見ない**ためです ── 件数を数えるところと転記するところの2か所とも

```vb
If ws.Range("A1").Value = "集計" And InStr(ws.Name, "_機側") > 0 Then
```

で、マクロが機側ライン用に作られたからです。紙の様式はほかのラインでも
同じなので、座標はそのまま合います。

- 集計タブに**「機側以外のシートも読む」**。コマンドは `--any-sheet`、
  点検スクリプトも `--any-sheet`
- 外れるのは**シート名の縛りだけ**です。`A1`が「集計」であることと
  **停止3枠の見出し**は変わらず見ます(別の様式を黙って読まないため)
- **使ったことは結果に書きます** ──「機側以外のシートも読みました(VBAは
  名前に「_機側」を含むシートだけ見ます)」。入れた時点でVBAと同じ結果では
  なくなるので、黙って広げません
- 逆に、機側以外のシートばかりで0行になったときは「機側以外のシートも読む
  を入れると、同じ様式なら読めます」と言い添えます

### ラインごとに分けて出します

どのラインでも拾い方は同じですが、**機側には板に無い欄**(コイル縦割・
横割・係数処理ﾛｯﾄ数)があります。1本にまとめると、どちらの行にも相手の
空の列が並び、どのラインの行かも分かりません。

- 出すCSVは**ラインごとに1本**:
  `機側データ集計_LS_2026.08.23-2026.08.27.csv` /
  `機側データ集計_HVC_2026.08.26.csv`
- **名前にラインが入るようになりました**(前は `機側データ集計_2026.08.23.csv`)。
  中身の並びは変わりません ── **どのラインでも同じ23列**(VBAの集計シートの
  まま)で、使わない欄が空になるだけです
- ラインは**シート名の「_」より後**から採り、日報管理ツールの呼び名に
  直します(`機側` → `LS`)。同じラインの行が、ブックからは「機側」、
  変換したCSVからは「LS」として別々に分かれないように
- **空欄の埋め方もラインごと**にしました。上詰めは「上の行」を見るので、
  混ぜたまま埋めると板の行に機側のロット№や用途名が入ります ── 分ける
  一番の理由がこれです
- 前に出した集計CSVを積み増すときは、**名前からラインを拾います**
  (23列のままなので、中身には入っていません)

## 1.5.0

**「停止3枠なのに読めないブック」を探せるようにしました。** 停止2枠の
ブックは今後出てこないので、見つけたいのは**3枠なのに拾われないもの**
だけです。

### 増えたもの

- 集計タブに**「確かめるだけ(CSVを書きません)」**。出力先が未設定でも
  実行できます ── 読めるかどうかを見るだけなので
- `scripts/ブックを点検.py` … フォルダをまとめて見て、1枚ずつ
  読める/読めないと理由を出します。最後に
  **「停止3枠なのに読めない: 0」**まで数えます(0でなければ終了コード1)
- 結果の一覧が**1シートにつき1行**になりました。1冊に何枚も入っている
  ブックで、最後の1枚しか出ていませんでした

### 言い方を変えたもの

拾わない理由を、**どの条件で外れたのか・実際の値は何か**まで出します。
「対象外」とだけ出ていては直しようがありません。

| 前 | いま |
|---|---|
| 対象外(A1が「集計」で名前に_機側を含むシートだけ) | シート名に「_機側」がありません(名前: 「2026年8月25日_HVC」) |
| 同上 | A1が「集計」ではありません(いまは「日報集計表」) |
| 見出しが違います(AA7 は…) | 停止2枠のブックです(作業時間が AA 列 ── 3枠より2つ左にずれています) |
| (何も出ない) | 拾える行がありません(終了時刻のL列が空なので、VBAも1行も拾いません) |

**「読めた」と「拾えた」は別です。** ○ で0行のときも、そう書きます。

### 分かったこと

ブックから集計したときと集計明細CSVから集計したときの行数の差
(32行 / 27行)は、**停止2枠のブックが混じっていたからではありません**
── そのブックは3枠です。差の5行は**内訳だけ書いて記号を書いていない行**で、
日報側(記号+時間)には残らないためです。3枠だけになっても、この差は残ります。

## 1.4.0

**変換が出したCSVを、そのまま機側データ集計の材料にできるようにしました。**
「本ツールで変換したCSVを集計に入れても『中身が分かりません』になる」
「変換すると年月／日付フォルダに4本出る。集計のときはフォルダごと入れても
認識してほしい」への答えです。

### 増えたもの

- **集計タブが、変換の出力CSVを読みます。** 日付フォルダをそのまま
  ドラッグしてください
  - `集計明細` … **行の材料。** 1行=1行で読みます(日付は行ごと)
  - `停止内訳` … 行にはせず、**停止の記号→内訳名**に使います
  - `集計` `計算内容` … 材料にならないので、受け取る前に外します
    (一度に100本なので、材料にならないものに枠を使わせません)
  - 見出しの名前は**移行元の定義から組み立てます** ── 書き写すと、
    向こうで名前を直したときにこちらだけ古くなり、黙って拾えなくなります
- **停止内訳CSVの置き場所**を設定部に足しました(2つめのパス)。移行元が
  v3.93.0 で入れた仕組み(`logic/stop_csv`)をそのまま使います ──
  **メモ帳で直せる一覧**で、分類ごとに、ここに行があれば参照用マスタより
  先に読みます。管理者の鍵が要りません
  - フォルダでも `停止内訳.csv` そのものでも受けます
  - **どちらから読めたかを設定部に出します**
    (`停止内訳: 12記号(設備停止=CSV / 不稼働=マスタ …)`)
  - CSVに直すところがあれば**行番号つき**で出します ── 読めない行を
    黙って捨てると、一覧から理由がひっそり消えます
  - コマンド版にも `--stop-csv` を足しました
- 集計で記号の名前が引けなかったときは、**記号のまま入れて、どの記号が
  引けなかったかを出します**。黙って空にしません

### 直したもの

- **実物の2025年のブックが、機側データ集計で1枚も拾われませんでした。**
  目印の `A1` は「集計」なのですが、xlsx の文字列には**ふりがな**(`rPh`)が
  入っていて、読み手がそれまで拾っていたため `集計シュウケイ` に
  なっていました。Excel の `Range("A1").Value` はふりがなを返しません ──
  **VBAが見ている値と違うものを見ていた**ことになります(`converter/cells.py`)。
  実物6冊で確かめたところ、ふりがなが付いているのは見出しと項目名だけで
  明細の値には1つも無く、**出てくるCSVは1バイトも変わりません**
- **裏に回って戻ると、止まったように見えていました**(触ると戻る)。
  ブラウザは隠れたタブの心拍を間引き、数分で凍結します。途切れると画面の
  占有が期限切れになり、戻ったときに覆いが出ていました。**誰も使って
  いないなら断る理由がない**ので、戻った時点で黙って取り直します
  (`screen.js` の `regain`)。ほかの画面が持っていれば取り直せないので、
  「画面は1枚」は変わりません。表に戻った瞬間に1回打つようにもしました
- 覆いが出たときに**占有を返す**ようにしました ── 使わなくなった画面が
  抱えたままだと、次の画面を開けるまで待たされます
- 設定の「入力フォルダ」が何に使うのか分からない、という声への答えとして、
  **空でよいこと**と、変換タブの「入力フォルダをそのまま読む」のときだけ
  使うことを欄の下に書きました

### 中身

- `vendor/` を移行元の **v3.96.0**(`4e80a50`)で採り直しました(48ファイル /
  約12,800行)。採り直しの手順を道具にしてあります
  (`scripts/写しを採り直す.py`)── `--line` を渡して走らせると
  `guess_line()` が呼ばれず、その中の遅延importが写らないので、
  **使う道を3つとも走らせます**
- 実物6冊(2026年5冊 + 2025年1冊)で、出たCSV24本が**前と1バイトも
  同じ**ことを確かめました。2026年の5冊は9項目すべて一致のまま
- 読み手を1つに寄せました(`converter/cells.py`)── 同じセルが読み手に
  よって違う値になるのを避けるため、変換側(先頭シート)も集計側(全シート)も
  ここを通ります。1冊につき**1回しか開きません**(名前と中身を別々に
  取っていたのを1回に)

実物の2025年ブック1本と、2026年ブック5本で確かめました(2026年の5本は
