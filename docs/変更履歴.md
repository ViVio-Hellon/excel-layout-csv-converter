# 変更履歴

版は `config/app.json` の `version` ただ1つが出どころです(帯のバッジ・
`/api/health`・診断情報がすべてここを読みます)。**メジャー.マイナー.
パッチの数字3つ**だけにします ── 端末はフォルダごとコピーして配るので、
「いまどれが入っているか」を聞かれたときに並べて比べられる番号が要ります。

| 上げるところ | いつ |
|---|---|
| メジャー | 配り方や使い方が変わり、手順書を読み直してもらう必要があるとき |
| マイナー | 画面や機能が増えたとき、構成を組み替えたとき |
| パッチ | 不具合を直したとき |

## 1.4.0

**変換が出したCSVを、そのまま機側データ集計の材料にできるようにしました。**
「本ツールで変換したCSVを集計に入れても『中身が分かりません』になる」
「変換すると年月／日付フォルダに4本出る。集計のときはフォルダごと入れても
認識してほしい」への答えです。

### 増えたもの

- **集計タブが、変換の出力CSVを読みます。** 日付フォルダをそのまま
  ドラッグしてください
  - `集計明細` … **行の材料。** 1行=1行で読みます(日付は行ごと)
  - `停止内訳` … 行にはせず、**停止の記号→内訳名**に使います
  - `集計` `計算内容` … 材料にならないので、受け取る前に外します
    (一度に100本なので、材料にならないものに枠を使わせません)
  - 見出しの名前は**移行元の定義から組み立てます** ── 書き写すと、
    向こうで名前を直したときにこちらだけ古くなり、黙って拾えなくなります
- **停止内訳CSVの置き場所**を設定部に足しました(2つめのパス)。移行元が
  v3.93.0 で入れた仕組み(`logic/stop_csv`)をそのまま使います ──
  **メモ帳で直せる一覧**で、分類ごとに、ここに行があれば参照用マスタより
  先に読みます。管理者の鍵が要りません
  - フォルダでも `停止内訳.csv` そのものでも受けます
  - **どちらから読めたかを設定部に出します**
    (`停止内訳: 12記号(設備停止=CSV / 不稼働=マスタ …)`)
  - CSVに直すところがあれば**行番号つき**で出します ── 読めない行を
    黙って捨てると、一覧から理由がひっそり消えます
  - コマンド版にも `--stop-csv` を足しました
- 集計で記号の名前が引けなかったときは、**記号のまま入れて、どの記号が
  引けなかったかを出します**。黙って空にしません

### 直したもの

- **実物の2025年のブックが、機側データ集計で1枚も拾われませんでした。**
  目印の `A1` は「集計」なのですが、xlsx の文字列には**ふりがな**(`rPh`)が
  入っていて、読み手がそれまで拾っていたため `集計シュウケイ` に
  なっていました。Excel の `Range("A1").Value` はふりがなを返しません ──
  **VBAが見ている値と違うものを見ていた**ことになります(`converter/cells.py`)。
  実物6冊で確かめたところ、ふりがなが付いているのは見出しと項目名だけで
  明細の値には1つも無く、**出てくるCSVは1バイトも変わりません**
- **裏に回って戻ると、止まったように見えていました**(触ると戻る)。
  ブラウザは隠れたタブの心拍を間引き、数分で凍結します。途切れると画面の
  占有が期限切れになり、戻ったときに覆いが出ていました。**誰も使って
  いないなら断る理由がない**ので、戻った時点で黙って取り直します
  (`screen.js` の `regain`)。ほかの画面が持っていれば取り直せないので、
  「画面は1枚」は変わりません。表に戻った瞬間に1回打つようにもしました
- 覆いが出たときに**占有を返す**ようにしました ── 使わなくなった画面が
  抱えたままだと、次の画面を開けるまで待たされます
- 設定の「入力フォルダ」が何に使うのか分からない、という声への答えとして、
  **空でよいこと**と、変換タブの「入力フォルダをそのまま読む」のときだけ
  使うことを欄の下に書きました

### 中身

- `vendor/` を移行元の **v3.96.0**(`4e80a50`)で採り直しました(48ファイル /
  約12,800行)。採り直しの手順を道具にしてあります
  (`scripts/写しを採り直す.py`)── `--line` を渡して走らせると
  `guess_line()` が呼ばれず、その中の遅延importが写らないので、
  **使う道を3つとも走らせます**
- 実物6冊(2026年5冊 + 2025年1冊)で、出たCSV24本が**前と1バイトも
  同じ**ことを確かめました。2026年の5冊は9項目すべて一致のまま
- 読み手を1つに寄せました(`converter/cells.py`)── 同じセルが読み手に
  よって違う値になるのを避けるため、変換側(先頭シート)も集計側(全シート)も
  ここを通ります。1冊につき**1回しか開きません**(名前と中身を別々に
  取っていたのを1回に)

## 1.3.3

**「読めなかった(原因不明)」の正体は、こちらの書き間違いでした。** 2025年の
ブックを入れたときに理由が出ず、原因が分からない状態になっていました。

- 読み取りの問題を出すところで、日報管理ツールの `Problem` に**無い名前**
  (`.message`)を読んでいました。例外が例外を呼び、本当の理由
  (`作業日(E1)が読めません: 2025/7/15`)が
  `'Problem' object has no attribute 'message'` にすり替わっていました。
  `reason` と行番号を、そのまま出すようにしました
- **作業日の書き方が年によって違いました。** `2025/7/15` `2025-07-15`
  `2025.7.15` `20250715`、Excelの日付の数(45853)を `2025年7月15日` として
  読みます(`converter/workday.py`)。直したことは**必ず画面とログに出す** ──
  「作業日を 2025/7/15 → 2025年7月15日 として読みました」。黙って直しません
- **シートが持っていない合計を、0として比べていました。** 2025年のブックは
  停止の合計(T4/V4/X4)が空のままで、空欄を0とみなすと
  「停止 合計(分): 読んだ数 870 / シート 0 ×」。**読めているのに、ずれて
  いると言う**のはいちばん悪い嘘なので、持っていないものは比べず
  「比べていない項目」として並べます(`converter/totals.py`)
- **シートが自分で食い違っているときは、そう言います。** 直合計
  16/34/12 が入っているのに日計が28のままのブックがありました(合計式が
  計算し直されていない)。直合計の足し算と比べ、
  「シートの日計(28)が直合計の足し算(62)と食い違っています」と出します

実物の2025年ブック1本と、2026年ブック5本で確かめました(2026年の5本は
**9項目すべて一致**のまま)。

## 1.3.0

**画面をタブで2つに分けました。** 変換と機側データ集計は使う場面が違い、
要る設定も違うためです。**画面は1枚のまま**で、2枚目をお断りする作りは

- **変換タブ** ── これまでどおり(ドラッグ or 入力フォルダ、4本組CSV)。

- **機側データ集計タブ** ── 専用のドラッグ投入。**Excelでも CSV でも受けます**

    (日付は作業日の欄 E1 から)
  - どちらでもないCSVは理由を出して飛ばす
  - **変換はしません** ── 集計だけ欲しいときに4本組CSVが出ません
- 受け取り置き場をタブごとに分けました(`work/intake/convert` と `…/tally`)
- 進捗と結果は1か所のまま(走る仕事は一度に1つ)。見出しは仕事の種類で変わります

## 1.1.0

**構成を `python-web-tools` にそろえました。** 起動基盤の作りを社内の他の
Webアプリと同じにして、覚えることを1つにするためです。動くものは変わって
いませんが、ファイルの置き場所と名前が変わりました。

- **業務と基盤を `converter/` へ集約**(参照側の `packaging_tool/` にあたる)。
  `app/` には画面層(`shell.py` / `routes/` / `templates/` / `static/`)だけを置く
  - `app/appinfo.py` → `converter/app_config.py`
  - `app/settings_store.py` → `converter/user_settings.py`
  - `app/screen.py` → `converter/screen_lock.py`
  - `app/logging_setup.py` → `converter/logging_utils.py`(`get_logger` へ)
  - `app/jobs.py` / `app/intake.py` → `converter/` 配下
- **待機画面を同じポートで出すようにしました**(`boot_server.py` +
  `converter/boot_screen.py`)。`loading.html` は廃止
  - 以前は `file://` で開いた待機画面が `http://` を叩いていたため、
    別オリジンの扱いになっていました。いまは**同じ待ち受け**が出すので、
    本体ができたら**開き直さずに**差し替わります(`Handover`)
- **起動トークンを入れました。** `/api/*` は起動ごとの合言葉が要ります
  ── 利用者が開いている別のサイトから操作されないため
  (`/api/health` と `/api/alive` だけは免除。理由は `app/__init__.py`)
- **自動終了を `converter/idle_exit.py` へ。** 心拍の間隔は
  `HEARTBEAT_MS` ただ1つが出どころ(画面とサーバで別に決めない)
- 経路を話題ごとに分割(`app/routes/health.py` / `screen.py` /
  `settings.py` / `input.py` / `job.py`)
- CSS を `tokens` / `base` / `layout` / `components` に分割。
  **色の出どころは `tokens.css` ただ1つ**で、待機画面もこれを読む
- JavaScript を ES モジュールに分割(`api` / `screen` / `health` /
  `toast` / `busy` / `progress` / `views/*`)
- `start.bat` / `stop.bat` を共有フォルダ対応(`pushd`)、`chcp 932`、
  引数の素通し(`--check` / `--status` / `--force`)に
- `requirements.txt`(**何も要らないことを書き残す**)、`scripts/`、
  `tests/_isolation.py` / `tests/_web.py` を追加。試験を話題ごとに分割

### 直したもの

- **生存確認が画面の占有を延長していませんでした。** 12秒で自分が
  締め出され、「接続中」のまま操作だけが断られる状態になっていました
  (`tests/test_screen_lock.py` が見張っています)
- `hidden` が class の `display` に負け、**見えない覆いが操作を吸って
  いました**(押しても何も起きない)。`base.css` で `!important` に
