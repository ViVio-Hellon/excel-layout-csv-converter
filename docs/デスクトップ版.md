# デスクトップ版 ── ポートを使わない窓

1.12.0 から、**同じ業務をそのまま窓の中で**動かせます。

| | ブラウザ版(予備として残します) | **デスクトップ版** |
|---|---|---|
| 起動するもの | `Start.vbs` / `start.bat` | **`ExcelCsvConverter.exe`** |
| 画面 | いつものブラウザのタブ | 窓(WebView2 ── Edgeの表示部分) |
| 通り道 | 127.0.0.1 の**ポート 8741** | **標準入出力**(ポートは1つも開きません) |
| 落とされたブック | 中身を送って写す(1本 50MB まで) | **本当の場所をそのまま読む**(写さない・上限なし) |
| 終わり方 | 画面の「アプリを終了」/ `stop.bat` | 窓の×・画面の「アプリを終了」 |

**画面の中身は同じです。** 同じHTML・同じJS・同じ `app/` を通ります。
変換と機側データ集計のコードには1行も手を入れていません(出てくるCSVは
バイトまで同じ ── `vendor/` の約束)。

## なぜポートを捨てるのか

ブラウザ版は、1台に1つのポートを前提にしています。そこから次の面倒が出ます。

- ポートを別のソフトが使っていると起動できない(端末ごとに違う)
- 社内のセキュリティ製品が 127.0.0.1 の待ち受けを止めることがある
- 「画面を1枚だけ」を守るのに、ポートの応答とPIDの両方を見る必要がある

デスクトップ版は、窓を持つ外枠(Rust/Tauri)が Python を**子として起動**し、
標準入出力で要求を渡します。**ソケットを1つも開きません**(`scripts/
デスクトップ版を確かめる.py` の③で毎回確かめています)。

```
ExcelCsvConverter.exe (Rust/Tauri)
   │  app://localhost/ への要求を受ける(Windowsでは http://app.localhost/)
   │
   ├─ 窓・×ボタン・終了の確かめ・落下したファイルの場所取り
   │
   └─ 子プロセス  python bridge.py
            │  見出し1行(JSON) + 本文(生のバイト列)
            ▼
         app.dispatch(Request) → Response
            │
            ▼
         converter/(変換・機側データ集計・設定・ログ)
```

言語の持ち場を分けています。

| | 任せたこと | なぜ |
|---|---|---|
| **Rust** | 窓・OSとのやりとり(落下したファイルの**本当の場所**・多重起動の錠・終了の確かめ) | ブラウザには取れないもの。ここだけがOS依存 |
| **Python** | 業務のすべて(ブックを読む・CSVを書く・集計・設定・ログ) | 日報管理ツールと**同じコード**を通すため。100冊を1.2秒で変換できており、書き換える理由がありません |

## 起動と終了

```
ExcelCsvConverter.exe          これ1つです(待機画面 → 業務画面)
```

窓が出ると、まず**待機画面**が出ます(ブラウザ版と同じものです)。Python が
「準備ができた」と言ってから業務画面へ切り替わります ── 秒数では切り替え
ません。

終わるとき:

| したこと | どうなるか |
|---|---|
| 画面の「アプリを終了」 | 確かめの覆いが出て、**終了する**を押すと片づけて窓も閉じます |
| 窓の×を押す | 同じ確かめが出ます(変換中は「中止してから」と断ります) |
| 外から exe を終わらせた | Python も一緒に終わります(取り残しません) |

## ブラウザ版とは**同時に動きません**

同じ出力先・同じ設定ファイル・同じログを2つが触ると、どちらが書いたのか
分からなくなります。**後から開いたほうが、自分で止まります**(先に動いて
いるほうには手を出しません)。

| 先に動いているもの | 後から開いたもの | 出るもの |
|---|---|---|
| デスクトップ版 | `Start.vbs` / `start.bat` | 「デスクトップ版が起動しています」(終了コード 5) |
| ブラウザ版 | `ExcelCsvConverter.exe` | 窓に「ブラウザ版が起動しています」と理由が出て閉じます |

見分け方は**目印 + PID + プロセスの起動時刻**です(`converter/
launch_marker.py`)。デスクトップ版はポートを開かないので、ポートの応答では
見分けられません ── 1.11.3 で入れた「番号の使い回しを見分ける」仕掛けを
そのまま使っています。

`stop.bat` も両方を見ます。デスクトップ版が動いていれば、**窓に閉じてくれと
頼み**(`--force` で強く)、目印が消えるまで待ちます。

```
stop.bat --status     デスクトップ版が起動しています(PID …/ポートを使いません)
stop.bat              窓に終了を頼みます
stop.bat --force      応答が無ければ終了させます
```

## 落とされたブックを写さない

ブラウザは落とされたファイルの場所を教えてくれないので、中身を送って
もらって `work\intake` へ写していました(1本 50MB まで)。窓は**本当の場所**
を教えてくれるので、デスクトップ版では**写さずにその場で読みます**。

- コピーが無くなります(100冊なら、まるごと1回ぶんのコピーが消えます)
- **1本の大きさの上限がありません**
- 片づけ(「受け取りを取り消す」)で消すのは、これまでどおり `work\intake` に
  写したものだけです ── **指された人のブックには触りません**

画面には「写さずにそのまま読みます」と出ます。

## 作る(Windows)

要るもの ── **配る端末には何も要りません**(作る人の端末だけです)。

| | |
|---|---|
| Rust | <https://rustup.rs>(`stable-x86_64-pc-windows-msvc`) |
| Visual Studio Build Tools | 「C++ によるデスクトップ開発」 |
| WebView2 | Windows 10/11 には入っています(Edgeと同じもの) |

```
cd src-tauri
cargo build --release
```

できるもの: `src-tauri\target\release\ExcelCsvConverter.exe`

GitHub Actions でも作れます(`.github/workflows/デスクトップ版をつくる.yml`)。
**成果物は配るフォルダまるごと**です(exe だけのものも別に出ます)。

| いつ | |
|---|---|
| **`main` に押すたび** | 自動で作ります ── **いつでも最新の exe があります** |
| `v…` のタグを押したとき | 配るぶん |
| 手で実行 | Actions → 「デスクトップ版をつくる」 → Run workflow |

終わったら、その実行の画面の下の **Artifacts → `ExcelCsvConverter-windows`**
から取ります(既定で90日残ります。配るぶんは社内の配布場所へ移してください)。

続けて押したときは、**前の実行を止めて最後のだけ**作ります
(Windows のランナーは使った分が Linux の10倍で数えられるため)。

アイコンを作り直すとき(追加ライブラリは使いません):

```
python scripts/デスクトップ版のアイコンを作る.py
```

## 配る

フォルダをまるごとコピーする、いままでの配り方のままです。
**exe 1つだけを入れ替えないでください** ── 画面も変換も Python 側
(`app\` `converter\` `config\`)にあり、版の帯に出るのは
`config/app.json` の版です。新しい exe だけを古いフォルダへ入れると、
**窓は新しいのに中身は古いまま**になります(画面には古い版が出るので
「exe が古い」に見えます)。

食い違っていれば、画面の帯に「**中身が古いままです**」と出ます
(窓が自分の版を Python へ渡して見比べています)。診断情報にも出ます。

Actions の成果物は **`ExcelCsvConverter-windows-<版>`**(フォルダまるごと)
を取ってください。`ExcelCsvConverter-exe-only-<版>` は、中身を入れ替えずに
窓だけ差し替えるときのものです。

```
ExcelCsvConverter\
  ExcelCsvConverter.exe   ← 増えたのはこれだけ
  Start.vbs  start.bat  stop.bat     ← 予備として残します
  bridge.py  start_app.py  server.py  convert.py
  app\  converter\  config\  vendor\  docs\
```

- **Python は同梱しません。** 端末に入っている Python を使います
  (`XLCSV_PYTHON` で場所を指せます。既定は `python.exe` → `py -3`)
- exe は自分の置かれたフォルダから上に向かって `bridge.py` を探します
  (`XLCSV_ROOT` で指せます)
- ログ・設定・作業フォルダはブラウザ版と**同じ場所**です

## 確かめる

```
python scripts/デスクトップ版を確かめる.py        （Linuxでは xvfb-run -a を付けます）
```

人が目で見るしかないもの以外を、通しで見ます。

| | 見るもの |
|---|---|
| ① | exe を起動すると Python(`bridge.py`)が子として起きる |
| ② | その Python が画面を返している(ログに「起動完了(デスクトップ版)」) |
| ②-2 | 窓が本当に画面を読み込んだ(真っ白ではない) |
| ②-3 | 画面が使える(「この操作は受け付けられません」の覆いが出ていない) |
| ③ | **どのプロセスもポートで待ち受けていない** |
| ④ | デスクトップ版の目印が置かれる(ブラウザ版はこれを見て断る) |
| ⑤ | exe を止めると Python も終わり、目印も片づく |

試験は `tests/test_bridge.py`(やりとりの形・本物の `bridge.py` を起こした
通し・同時起動の断り)。

## 確かめきれていないこと(Windowsで人が見ます)

ここまでは Linux の WebKitGTK で通しています。**Windows でしか確かめ
られないもの**が残ります。

- 窓の見た目(WebView2 での表示崩れ・フォント・倍率)
- **ドラッグ&ドロップ**(本当の場所が来るか。フォルダごと落とした場合も)
- 印刷(画面からの印刷)
- ブラウザ版との同時起動の断り(両方向)
- `stop.bat --force` で窓が閉じるか
- Python が無い端末・`py -3` だけの端末での起動と、その理由の出方
